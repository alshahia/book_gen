## WARN-9: DEFERRED (all 5 accept-as-design)

### Why DEFERRED, not MIXED or RESOLVED

AG16's own verdict at `share/reports/04_review_T-2026-07-04-001.md:207` was: "not a WCAG violation (SR-only users get section flow via the skip-link); DEFERRED per the Outstanding Items." The audit's tool evidence (4/4 keyboard-nav checks PASS) and the skeleton implementation together support that verdict:

1. **Keyboard nav contract is already implemented and tested.** `memory/13-keyboard-nav.md:105-110` specifies the 4-step manual test (Tab → skip-link → Enter; PageDown ×6 cycles sections; Tab into CTA + arrow keys; PageUp from CTA). The skeleton passes that test post-fix-loop-2 — `skeleton/index.html:1152-1187` is the PageDown/PageUp listener, the universal `:focus-visible` ring is at `:164`, and the section-level `tabindex="-1"` is on every flagged section.
2. **AG16 measured 18 focusable elements, not 18 - 5 = 13.** The "zero focusable elements in hero/film/reveal/ritual/editions" reading is correct for the BODY of each section but is not a violation — those sections have no actionable content beyond their inner text (and where they DO have inner elements, like `editions`'s cards, those elements are deliberately non-interactive).
3. **The "focus-receiver" decision is already applied.** Per the brief's own definition ("add `<section ... tabindex="-1">`"), every one of the 5 sections already has section-level `tabindex="-1"`. The optional `<h2 tabindex="-1">` half of the focus-receiver pattern would be additive markup without behavior change — `skeleton/index.html:1182` targets the section element, so even if a `<h2>` had `tabindex="-1"`, PageDown focus would still land on the section. **Adding it would be pure redundancy, not a fix.**
4. **The "skip-link" decision would add 5 new off-screen links** without making the 5 sections Tab-reachable. Skip-links add a Tab-stop at the START of the next page region; they do not place the target region IN the Tab order. The same niche user (Tab-only, no PageDown, no SR) who can't reach `hero` today still couldn't reach it via a skip-link — they'd just see another skip-link first.

### Why this ratifies the existing contract (no contradiction with memory/13)

`memory/13-keyboard-nav.md` defines the canonical keyboard interface as **PageDown/PageUp for section traversal** (line 11), NOT Tab. WARN-9 documents the corner case where a user who only uses Tab (no PageDown, no SR landmarks) can't reach the 5 static sections. These two views are **complementary, not contradictory**: memory/13 says "this is how power keyboard users navigate sections," and WARN-9 says "this is the gap for a Tab-only user with no SR." The existing implementation satisfies the documented contract. Closing the Tab-only gap would require either (a) `tabindex="0"` on sections (which memory/13:118 explicitly forbids — would put every section into the Tab order, breaking the focus-order contract), or (b) a Tab-walking alternative (e.g., arrow-key roving) explicitly out-of-scope per the task brief at `tasks/T-2026-07-04-003.md:25-26`.
