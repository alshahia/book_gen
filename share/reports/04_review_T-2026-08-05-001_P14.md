- **`check_imports` namespace-package gap**: the rule does not handle distribution-name vs import-name mismatches (e.g., `from PIL import Image` with `Pillow` in uv.lock). This is a real but uncommon edge case; fix would be a small `{import_name: distribution_name}` mapping table. **P14.x candidate.**

- **`pin_deps.py` lock format gap**: `_LOCK_LINE_RE` at `pin_deps.py:49` and `check_chapter.py:685` only matches `name==version` shape (uv 0.7.x default). If uv switches to PEP 751 `[[package]]` blocks in a future version, both scripts degrade to `packages=0 lock_status=pinned` and `0 imports verified`. **Not a crash, but a future-patch candidate.** Documented by coder at coder summary line 105.

- **Plant test #5 design choice**: pin_deps.py exits 0 on per-chapter compile failures and surfaces them as `compile_failed` status rows. This deviates from the dispatch's "exit non-zero with clear stderr" wording, but the design is defensible (the status file is the audit trail; a non-zero exit would mask other chapters' results). **Master's call whether to overturn.** Reviewer recommendation: **accept as-is**; any pipeline consumer that wants exit-on-any-failure can grep `CH-DEP-STATUS.md` for non-`pinned` rows.
