## Coder-flagged deviation adjudication

**Deviation:** `parallel_search.py` consumes pre-fetched JSON results from `--exa-results` / `--firecrawl-results` instead of invoking the MCP servers directly.

**Adjudication: ACCEPTED.** This is FORCED by the MCP architecture:
- Plan §P9 line 222 says "Calls Exa + Firecrawl in parallel (Exa via built-in `websearch` permission + explicit MCP)" — both are remote OAuth MCPs (`https://mcp.exa.ai/mcp`, `https://mcp.firecrawl.dev/v2/mcp-oauth`).
- MCP servers with `type: "remote"` are HTTP-only; Python cannot invoke them directly (no stdio JSON-RPC, no OAuth dance from inside `subprocess`).
- The LLM is the only tool-capable client for MCP. So the LLM does the parallel `tool_use`, writes the result lists to temp files, then invokes this CLI for dedup + tagging + trail.
- The pure function `parallel_search(exa_fn, firecrawl_fn, ddg_fn, trail_path)` also accepts injected callables, so programmatic callers (tests, future Python callers) don't need temp files.
- This matches the locked decision in `share/notes/99_decisions.md` (2026-08-05 entry, line 119-122).
