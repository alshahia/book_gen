## Out-of-scope observations

1. **`quote_pair_balance` does NOT apply `outside()` (code-fence skip) for its top-level count** — only the per-paragraph nested check does (`check_chapter.py:247`). If a chapter has `«`/`»` inside a code fence (e.g., a code sample showing how to type these characters), the top-level parity check could over- or under-count. In practice this is extremely unlikely (Arabic code samples rarely contain `«`/`»`), but it's an inconsistency vs. the other 7 rules which all use `outside()`. **WARN** — could be fixed with a 1-line `clean = outside(chapter_md); opn = clean.count("«"); cls = clean.count("»")`. Not blocking.

2. **`_write_chapter` and `_results_for(..., tmp_project=None, ...)` are dead code** — defined but never invoked by any test (`test_check_chapter.py:27-31, 35`). Either the tests should be refactored to actually create the fixture files on disk (matching the docstring claim at line 4: "writes a tiny fixture chapter to `tmp_project/chapters/`") OR the helper should be deleted. **WARN** — cosmetic, but the docstring overpromises.

3. **`test_happy_path_all_pass` uses `chapter_name="ch-test.md"`** — the `countdown` rule's `_chapter_number_from_path` regex `r"ch-(\d+)"` doesn't match `ch-test`, so the countdown rule emits PASS-with-skip-evidence rather than truly validating that a numbered chapter with countdown tokens passes. Test #7 separately validates FAIL on a numbered chapter (`ch-05.md`), but there's no positive test for countdown PASS on a numbered chapter. **WARN** — coverage gap, not a correctness gap.

4. **Coder reported "10 pre-existing failures"** with `WinError 6` handle-exhaustion — my full-suite run shows 89/89 pass with the same Python 3.14 + Windows environment. The diagnostic is unreliable. The gate is met (no regressions), but the "confirmed pre-existing by stashing" assertion is not reproducible from this run. **WARN** — surface to master that the failure may be flaky/intermittent rather than deterministic.

5. **`sentence_length` median computation** uses `lengths[len(lengths)//2]` — for an even-length list, this picks the upper-middle value (e.g., [3,4,5,6] → index 2 → 5), not the average of the two middle values. This is one common interpretation of "median"; not blocking. Mentioned for future reference.

6. **Default 600-750 window applied per-beat is unrealistic for most books** — the plan spec is `(600, 750)`, which makes sense for per-chapter totals but not per-beat. A 25-page chapter has 8 H2 beats of ~150-330 words each, all of which will FAIL the lower bound. The coder correctly flagged this as a real-world waiver requiring custom frontmatter (`Beat window: 100 - 500` per book). This is **per-spec behavior**, not a bug. **Documented in `docs/SCRIPTS.md:78` and the coder's deviations list. NOT a WARN.** Just a reminder for users.
