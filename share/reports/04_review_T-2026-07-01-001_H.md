### N2 — `[CRITICAL]` PowerShell `skills add --all` via `powershell -File` BROKEN

**Severity: CRITICAL.** `python3 bin/agents-manager.py skills add --all --local --yes` (and any `skills add` invocation with `--all`) fails on Windows with a parameter-binding error:

```
E:\context_gen\bin\agents-manager.ps1 : A positional parameter cannot be found that accepts argument 'skills'.
    + CategoryInfo          : InvalidArgument: (:) [agents-manager.ps1], ParentContainsErrorRecordException
    + FullyQualifiedErrorId : PositionalParameterNotFound,agents-manager.ps1
```

**Root cause**: PowerShell's parameter binder is case-insensitive and uses prefix matching. The script's `param([Parameter(ValueFromRemainingArguments=$true)] [string[]]$AllArgs)` declaration makes `$AllArgs` bindable by `--all` (because `AllArgs` and `All` share the prefix `All` — and PowerShell's case-insensitive prefix matching considers them the same parameter). When `--all` is bound as a named parameter to `$AllArgs`, the remaining positional args (`--local --yes`) can't be bound to anything (since `$AllArgs` is now already "used up" as a named parameter).

**Reproduction matrix** (all via `subprocess.run(["powershell", "-NoProfile", "-File", "agents-manager.ps1", ...])`):

| Invocation | Exit | Result |
|---|---|---|
| `skills list` | 0 | works |
| `skills list --missing-only` | 0 | works |
| `skills add foo` | 0 | works |
| `skills add foo --yes` | 0 | works |
| `skills add --all` | 1 | `Missing an argument for parameter 'AllArgs'` |
| `skills add --all --yes` | 1 | `positional parameter cannot be found … 'skills'` |
| `skills add --all --local` | 1 | same error |
| `skills add --all foo` | 1 | same error |
| `skills add --all --local --yes` | 1 | same error |

**Works correctly** when invoked via `pwsh -NoProfile -Command "& ./bin/agents-manager.ps1 skills add --all --local --yes"` (call operator) — the parameter binder doesn't apply the same prefix-matching rule.

**Works correctly** via bash dispatcher when invoked directly (when bash is non-empty; verified by `python3 -c "import subprocess; subprocess.run(['bash', 'bin/agents-manager', 'skills', 'add', '--all', '--local', '--yes'], ...)"` — exit 0 with proper plan printed). Bash `cmd_skills_add` correctly handles `--all`.

**Why this is a CRITICAL regression and not just a missing test**: This bug is **pre-existing** (not introduced by fix loop G), but was not caught by either the prior review (which only verified `skills list` and `skills which` worked end-to-end through Python) or the fix loop (which verified only the `install` path). The bug is reachable through the most common user-facing commands on Windows.

**Scope**: Affects Windows only. On Linux/macOS the Python wrapper calls bash directly, which handles `--all` correctly.

**Suggested fix** (do NOT apply per soft-wall — surface only):
- **Option A (smallest diff)**: rename `$AllArgs` to something that doesn't prefix-match any user-facing flag (e.g., `$RemainingArgs` or `$RestArgs`). Then `--all` won't be misinterpreted.
- **Option B**: use `[Parameter(ValueFromRemainingArguments=$true, Position=0)] [string[]]$AllArgs` with explicit Position binding — but this is more invasive.
- **Option C**: catch-all via `$args` automatic variable (deprecated for scripts but still works).

Recommend Option A for the next fix loop.
