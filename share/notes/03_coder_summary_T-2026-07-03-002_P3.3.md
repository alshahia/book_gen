- `agents_manager/{research,planning,design,coder,review,assets}/notes/semantic/` — role scope (semantic)

So the strict 3-value enum check (`global|project|role`) is correct. Decision documented inline as a code comment per dispatch.

**Note on `canonical-pointer` scope value:** `agents_manager/assets/notes/README.md` uses `scope: canonical-pointer` (chunk 2 4th-value family). Same reasoning: the file lives at `agents_manager/assets/notes/`, NOT under `notes/semantic/` or `notes/episodic/`, so it's not walked. No code change needed.

**Per-file checks:**
1. Frontmatter opens (`---` on line 1) — strip CR first to handle CRLF
2. Frontmatter closes (later `---`) — search starts at line index 1 to skip the opener
3. Required keys present (`scope`, `topic`, `status`, `created`, `last_verified`) — uses `${fm[$k]+x}` to safely check presence under `set -u`
4. `scope ∈ {global, project, role}` — case-statement
5. `status ∈ {active, superseded}` — case-statement
6. `created` and `last_verified` match `^[0-9]{4}-[0-9]{2}-[0-9]{2}$` AND parse via `date -d ... +%Y-%m-%d >/dev/null 2>&1` (GNU; regex still catches obvious non-dates if `date -d` unavailable)
7. If `status: superseded` → `superseded_by:` key must be present (value not validated)

**Exit codes:** `0` = zero FAILs; `1` = at least one FAIL. Output: `OK: <count> entries validated` on stdout always; `FAIL : <path> : <reason>` on stderr per failure.
