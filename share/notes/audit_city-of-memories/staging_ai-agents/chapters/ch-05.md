## Keep changing values in a list

A list is an ordered, changeable collection. Square brackets hold its items, and positions start at zero. Lists are useful for tasks, messages, tool results, or any group whose contents may grow or shrink while a program runs.

```python
tasks = ["read", "test", "report"]

print(tasks[0])
print("test" in tasks)

tasks.append("archive")
tasks.remove("read")
last_task = tasks.pop()

print(tasks)
print(last_task)
print(len(tasks))
```

`append()` adds one item at the end. `remove()` deletes the first matching value. `pop()` removes and returns an item, using the last item when you omit an index. `len()` counts items, while `in` returns a Boolean membership result.

The Python tutorial notes two useful failure signals. An index outside the list raises `IndexError`, and `remove()` raises `ValueError` when the requested value is absent. Check membership before removal when absence is expected. Keep ch-04's rule too: don't add or remove items from the list you're currently iterating over.

## Keep fixed positions in a tuple

A tuple is also ordered, indexed, and sliceable, but it can't be changed after creation. Parentheses make the grouping clear, while the commas create the tuple. Use a list when items will change and a tuple when each position has a stable meaning.

```python
location = (3, 5)
x_coordinate, y_coordinate = location

print(location[0])
print(x_coordinate)
print(y_coordinate)

try:
    location[0] = 4
except TypeError as error:
    print(type(error).__name__)
```

The assignment inside `try` raises `TypeError` because tuple items don't support assignment. The line `x_coordinate, y_coordinate = location` is tuple unpacking: Python assigns one item to each name. The number of names must match the number of items unless you use a starred name to collect the remainder.

A tuple containing only immutable values can be a dictionary key. A list can't, and a tuple that contains a list can't either. That distinction matters when one record needs a multi-part key such as `(latitude, longitude)`.

## Compare unique items with sets

A set stores unique items without positions or a guaranteed iteration order. It works well for removing duplicates and answering membership questions. Set items must be hashable: an object is hashable if Python can compute a stable integer identifier for it (using its `__hash__()` method); numbers, strings, and tuples of hashable values are hashable, while lists and dictionaries are not because they can change.

```python
planned = {"read", "code", "test"}
finished = {"read", "review", "test"}

print(sorted(planned | finished))
print(sorted(planned & finished))
print(sorted(planned - finished))
print(sorted(planned ^ finished))

empty_set = set()
empty_dict = {}
assert isinstance(empty_set, set)
assert isinstance(empty_dict, dict)
```

The `|` operator produces the union, containing items from either set. `&` produces the intersection, containing items in both. `-` produces the difference, containing items only in the left set. `^` produces the symmetric difference, containing items in one set but not both.

`sorted()` appears only to make the printed order predictable. A set has no first item, so indexing such as `planned[0]` raises `TypeError`. The empty form is another important distinction: `set()` creates an empty set, while `{}` creates an empty dictionary.

## Find values by key in a dictionary

A dictionary maps unique keys to values. Instead of asking for position zero, you ask for a descriptive key such as `"task"` or `"status"`. Strings are the usual beginner keys, though numbers and immutable tuples also work.

```python
run = {"task": "summarize", "steps": 3}
run["status"] = "ready"

print(run["task"])
print(run.get("model", "not selected"))

for key, value in run.items():
    print(f"{key}: {value}")
```

Square-bracket lookup raises `KeyError` when a key is missing. The safer `get(key, default)` form returns its default instead, which fits optional data. Assigning through a new key adds a pair, while assigning through an existing key replaces its value.

Python has guaranteed dictionary insertion order since version 3.7, so `items()` visits keys in the order they were first added. Replacing a value doesn't move its key. That guarantee helps CSV headers and human-readable JSON stay consistent.

## Reuse sequence operations on strings

Strings behave like lists for several read operations. Both support zero-based indexing, slicing, `len()`, and membership tests. On a string, `in` searches for a substring, so `"notes" in "agent notes"` is `True`.

```python
label = "agent notes"

print(label[0])
print(label[0:5])
print(len(label))
print("notes" in label)

updated_label = "A" + label[1:]
print(updated_label)
```

Strings differ from lists because they're immutable. Assigning to `label[0]` raises `TypeError`. Build a new string through slicing, concatenation, or a string method instead, as `updated_label` does above.

## Close text files with `with`

A file lets data survive after the program exits. Python's `open()` returns a file object, and the `with` statement closes that object when the indented block ends, including when an exception interrupts the block.

```python
path = "agent_notes.txt"

with open(path, "w", encoding="utf-8") as f:
    f.write("first note\n")
    f.write("café review\n")

with open(path, encoding="utf-8") as f:
    for line in f:
        print(line.rstrip())
```

Mode `"r"` reads and is the default. Mode `"w"` writes and replaces an existing file. Mode `"a"` appends at the end. `write()` doesn't add a newline, so include `\n` when you want one. Iterating over the file reads one line at a time.

Always pass `encoding="utf-8"` for text. The platform default can differ, while UTF-8 preserves the same text across Windows, macOS, and Linux. The Python tutorial presents `with open(...)` as the default because automatic closing is safer than pairing a bare `open()` with a later `close()`.

## Read and write CSV rows

CSV represents a table as rows and fields. Python's standard-library `csv` module handles commas, quotes, and line endings. Open its files with `newline=""` so the module controls line endings and Windows doesn't gain extra blank rows.

```python
import csv

path = "tasks.csv"

with open(path, "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["task", "owner", "done"])
    writer.writerow(["read", "Ada", "yes"])
    writer.writerow(["test", "Lin", "no"])

with open(path, newline="", encoding="utf-8") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
```

`csv.reader` yields each row as a list of strings. `csv.writer` accepts lists and provides `writerow()` for one row or `writerows()` for several. The default comma-separated format covers the usual case without a custom dialect.

When the first row contains column names, `csv.DictReader` yields one dictionary per data row. `csv.DictWriter` takes `fieldnames`, needs one `writeheader()` call, and then accepts dictionaries through `writerow()` or `writerows()`. Values read from CSV are strings, so convert them explicitly when your program needs numbers or Booleans.

## Preserve structured data with JSON

JSON can represent nested dictionaries and lists as text. The standard-library `json.dump()` function writes one Python value to a file, while `json.load()` reads one JSON document back into Python.

```python
import json

path = "run_state.json"
state = {
    "owner": "Zoë",
    "tasks": ["read", "test"],
    "active": True,
    "note": None,
}

with open(path, "w", encoding="utf-8") as f:
    json.dump(state, f, ensure_ascii=False, indent=2)

with open(path, encoding="utf-8") as f:
    loaded_state = json.load(f)

assert loaded_state == state
print(loaded_state["owner"])
```

`ensure_ascii=False` keeps Unicode text such as `Zoë` readable instead of escaping it. `indent=2` lays out nested values across lines. These options make files easier to inspect while `json.load()` still reconstructs the same supported Python values.

The supported-types cheat sheet is short: JSON strings map to `str`; numbers map to `int` or `float`; `true` and `false` map to `True` and `False`; `null` maps to `None`; arrays map to `list`; and objects map to `dict` with string keys.

Two types need care. A tuple is written as a JSON array and comes back as a list, so convert it to a list when that change is intentional. A set is rejected with `TypeError`; convert it to a list, often with `sorted(my_set)` for stable order. Custom class instances are rejected too, so turn their needed fields into a supported dictionary first.

## Check: turn a CSV file into JSON

Run this from a temporary practice folder. It creates a small CSV, reads dictionaries from it, writes JSON, reads that JSON back, and raises `AssertionError` if the saved data changed.

```python
import csv
import json

csv_path = "tasks.csv"
json_path = "tasks.json"
fieldnames = ["task", "done"]
rows = [
    {"task": "read", "done": "yes"},
    {"task": "test", "done": "no"},
]

with open(csv_path, "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()
    writer.writerows(rows)

with open(csv_path, newline="", encoding="utf-8") as f:
    loaded_rows = list(csv.DictReader(f))

with open(json_path, "w", encoding="utf-8") as f:
    json.dump(loaded_rows, f, ensure_ascii=False, indent=2)

with open(json_path, encoding="utf-8") as f:
    saved_rows = json.load(f)

assert saved_rows == rows
print(saved_rows)
```

Expected output:

```text
[{'task': 'read', 'done': 'yes'}, {'task': 'test', 'done': 'no'}]
```
