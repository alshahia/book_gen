# Chapter 9 — Build a First smolagents Agent

A terminal opens, the prompt reads `agent.run("summarize https://example.com")`, the model thinks, prints `[Step 1: Calling web_search]`, fetches the page, prints `[Step 2: Calling summarize]`, and returns a two-paragraph summary to your script. If any step errors, the framework retries; if it can't recover, it surfaces a structured exception. This chapter is the chapter where that loop becomes yours.

Coming from ch-08: last chapter you built a 30-line plain-Python loop that prompts a model, parses the model's reply as JSON, dispatches a tool by name, and feeds the result back until the model emits a structured stop. This chapter keeps the same loop and hands it to smolagents, the framework that does the loop for you.

## Why use a framework

The toy agent had five moving parts you wired by hand: prompt assembly, action parsing, name-to-tool dispatch, the observe–decide–act–observe step loop, and the structured stop signal. None of those parts went away in a framework. What a framework buys you is packaging and a few extras smolagents adds on top.

smolagents packages the four steps you already wrote. The parser reads the model's reply and turns it into a typed tool call, including the parallel-call case your toy agent could not handle. The dispatch table routes that call by name to the right `@tool` function. The step loop runs the iteration until the model signals it is done.

The stop signal is a built-in terminator that the model calls when it has decided on an answer; the framework returns that value and ends the loop.

What smolagents adds is what your toy could not do: typed schemas (parameter names and types enforced at the tool boundary), retry-able step errors (parse failures and tool errors surface as structured exceptions the agent can react to), and agent-aware tool errors (a tool exception carries the failing call's metadata so the agent knows which call to revise). You write one tool, the framework does the bookkeeping.

## Meet the import line

```python
from smolagents import CodeAgent, ApiModel, InferenceClientModel, tool, FinalAnswerTool
```

> **Naming note (read once).** `HfApiModel` was the older name for the Hugging Face Inference API class in earlier smolagents releases; in smolagents 1.26.0 it has been renamed `ApiModel`. The renamed class is now the abstract base, and instantiating it directly raises `NotImplementedError`; the concrete beginner-friendly class that works out of the box is `InferenceClientModel`, which the runnable example below uses. This is the only rename the book flags; later chapters use the new names without repeating the note.

One import line, five names, three jobs. `CodeAgent` is the agent class that runs the loop. `tool` is the decorator that turns a typed function into something the agent can call by name. `FinalAnswerTool` is the built-in terminator the agent uses to return the answer and stop. `ApiModel` is the renamed base class (imported so this chapter can show it once). `InferenceClientModel` is the concrete Hugging Face Inference API client you instantiate.

## Construct a model

The agent needs a model object that knows how to send a prompt to a provider. The beginner-friendly class for the Hugging Face Inference API is `InferenceClientModel`.

```python
import os

from smolagents import InferenceClientModel


def load_api_key(name: str) -> str:
    token = os.getenv(name)
    if not token:
        raise SystemExit(f"Set {name} in .env or your shell.")
    return token


def build_model():
    load_api_key("HF_TOKEN")
    return InferenceClientModel(model_id="Qwen/Qwen2.5-Coder-7B-Instruct")
```

Two knobs and you are done. `model_id` selects which model answers; the rest of the constructor has safe defaults for retries and rate limits. The class pulls the token from the `HF_TOKEN` environment variable when `token=` is omitted, matching the `load_dotenv()` + `os.getenv()` pattern from ch-02 and ch-07. The `load_api_key` guard gives a clean "missing token" message before any API call, the same pattern ch-07 taught.

The package default model id in 1.26.0 is an 80B reasoning model that is not a beginner default; this chapter picks a coder-tuned 7B model from the Qwen 2.5 family, which fits the CodeAgent paradigm and stays small enough to reason about. Provider model names age quickly, so treat the model id as directional; pick a small coder model on the Hub that your `HF_TOKEN` is authorized to call. `InferenceClientModel` is documented in the smolagents 1.26.0 reference at https://smolagents.org.

## Build the agent

A `CodeAgent` needs two things at construction time: a list of tools and a model.

```python
from smolagents import CodeAgent

from word_count_tool import word_count  # an @tool-decorated function

agent = CodeAgent(tools=[word_count], model=build_model())
```

Save the `@tool`-decorated function to a file named `word_count_tool.py` in the same folder as the script that constructs the agent.

`tools=[...]` is a Python list of `@tool`-decorated functions. `model=...` is a `Model` instance. Anything else — sandbox executor, planning interval, managed agents, step callbacks — has a safe default and is deferred to a later chapter. Pass an empty list (`tools=[]`) when the agent should only run its own Python and call the built-in terminator, which is what the first "Hello, world" run does. `CodeAgent` is defined in the installed smolagents==1.26.0 source at `agents.py:1505`.

## Write a `@tool` function

The `@tool` decorator reads the function's name, parameter type hints, return type hint, and docstring and turns them into a structured description the agent can reason about. Three rules must hold.

```python
from smolagents import tool


@tool
def word_count(text: str) -> int:
    """Count whitespace-separated words in a string.

    Args:
        text: The input text to count words in.
    """
    return len(text.split())
```

Every parameter needs a type hint. The return value needs a type hint. The docstring needs a function description and an `Args:` block listing each parameter. Vague docstrings make the agent skip the tool; specific docstrings with concrete argument descriptions make the agent pick the tool. The decorator raises `TypeHintParsingException` if a hint is missing, so a half-decorated tool fails loudly at import time rather than at `.run()` time. The `@tool` decorator is defined in the installed source at `tools.py:1061`.

## Run the agent

To ask the agent to do something, call `.run(task)` with a plain English string.

```python
answer = agent.run(
    "How many words are in 'the quick brown fox jumps over the lazy dog'?"
)
print(answer)
```

`agent.run(task)` returns the answer by default. Internally, the framework drives the same observe–decide–act–observe loop you wrote by hand, except the model writes Python that the framework executes for it through a sandboxed executor. The call blocks until the agent reaches its stop signal or its step budget, which defaults to twenty steps.

For deeper inspection, pass `return_full_result=True` and capture a `RunResult` object instead.

```python
result = agent.run(task, return_full_result=True)
print(result.output)
print(result.state)
print(result.token_usage)
print(result.steps)
```

`RunResult` exposes the final answer on `.output`, the run state on `.state` (either `"success"` or `"max_steps_error"`), the per-step token usage on `.token_usage`, and the recorded memory steps on `.steps`. Streamed runs (`stream=True`) yield each step as it executes; that knob is deferred to ch-11. `MultiStepAgent.run` is at `agents.py:436`; the `RunResult` dataclass is at `agents.py:196`.

## Watch the step loop

Each iteration of the agent loop is one step. The model proposes a code block or a tool call, the framework runs it through a sandboxed Python executor, the printed output is captured, and that output becomes part of the next prompt. The framework repeats this until the model calls a built-in terminator or the step budget runs out.

You can see the loop without writing a callback. The `MultiStepAgent` constructor accepts a `verbosity_level` argument that defaults to `LogLevel.INFO`; passing `LogLevel.DEBUG` prints every step's code block, observation, and timing line. For programmatic observation, `step_callbacks=[my_fn]` runs the callback once per `ActionStep`, which is what ch-13 covers in depth.

## End the loop with the built-in terminator

The agent knows it is finished because there is a built-in terminator tool whose only job is to hand back whatever value the model decided on. The model writes a code block that calls the terminator with an answer, the framework detects the call, breaks out of the loop, and returns that value to your code as the answer.

`FinalAnswerTool` is added to every agent's tool list automatically — the parent class installs it via `setdefault` on the tools dictionary — so even an agent constructed with `tools=[]` still has the terminator and can stop the loop. You do not write a custom termination condition at this level. ch-12 introduces validators you can attach to the answer to gate it before the framework accepts it. The auto-installation lives in `MultiStepAgent._setup_tools` at `agents.py:389-403`; the `setdefault` call itself is at `agents.py:402`.

## Read the sandbox caveat

By default, `CodeAgent` runs the model-generated Python through a custom `LocalPythonExecutor` that walks the AST, denies most imports by default, caps total operations, and blocks access to unauthorized submodules. That is a layer of protection, not a security guarantee. The smolagents secure-execution guide is explicit: no local sandbox can ever be 100% safe, and robust isolation requires a remote executor such as Docker, E2B, Modal, or Blaxel.

The beginner rule for ch-09 is to keep the first runs on small, harmless tasks — arithmetic, a word count, a single tool call. Real sandbox choices (the `executor_type="docker"` knob, the `authorized_imports=` whitelist, the `final_answer_checks=` gate) are deferred to ch-14, where the safety surface is the chapter's topic.

## Run the agent without a token

Sometimes you want to see the loop run end-to-end without setting up a Hugging Face token or making a network call. A stub model is a small class that subclasses `Model` and overrides `generate` to return a fixed answer.

```python
import os

os.environ.pop("HF_TOKEN", None)

from smolagents import CodeAgent
from smolagents.models import ChatMessage, MessageRole, Model


class StubModel(Model):
    """Returns a fixed final answer without ever calling the network."""

    def __init__(self):
        super().__init__(model_id="stub/no-network")

    def generate(self, messages, **kwargs):
        return ChatMessage(
            role=MessageRole.ASSISTANT,
            content='<code>final_answer("42")</code>',
        )


def main():
    agent = CodeAgent(tools=[], model=StubModel())
    result = agent.run("What is the answer to life, the universe, and everything?")
    assert result == "42"


if __name__ == "__main__":
    main()
```

Wired in place of `InferenceClientModel`, the stub runs the full loop locally: the framework sees the model emit a terminator call with `"42"`, extracts it from the `<code>` wrapper, executes it through `LocalPythonExecutor`, detects the terminator call, and returns `"42"` to your code. No token, no network. The same stub pattern becomes the test fixture in ch-13, where every agent test runs against a canned `generate`.

## Fix four beginner errors

These four failures appear before any advanced feature. Name the failure, then apply the smallest fix.

1. **Forgetting `HF_TOKEN`.** The model object constructs fine; the first call to the provider returns HTTP 401. Traceback category: `HfHubHTTPError`. Fix: keep the `load_api_key("HF_TOKEN")` check before the model is built, the same guard ch-07's examples use.

2. **Wrong or private model id.** Pointing `model_id` at a non-existent repository returns HTTP 404 from the Hugging Face Hub. Traceback category: `HfHubHTTPError`. Fix: read the model-id line in the error and replace it with a model id your `HF_TOKEN` is authorized to call.

3. **Vague tool docstring.** The agent ignores the tool and falls back to its own Python or fails to converge. Traceback category: none (the run runs longer than expected and burns tokens without producing an answer). Fix: write a specific docstring with a one-line description and an `Args:` block listing each parameter, like the `word_count` example above.

4. **Forgot to import the tool function.** Building the agent raises `NameError` at construction time, not at `.run()` time. Traceback category: `NameError`. Fix: import the decorated function in the same module that constructs the agent — the decorator runs at import time, so the tool exists by the time `CodeAgent(...)` is called.

> **The move:** Import the framework, write one typed `@tool` function with an `Args:` docstring, construct an `InferenceClientModel` with `HF_TOKEN` loaded, build a `CodeAgent(tools=[your_tool], model=model)`, and run `.run(task)` against a small task — then run the same loop with the stub model when you don't have a token.
