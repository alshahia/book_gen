## Give values readable labels

Python represents data as objects. The Python data model says every object has a type and a value, while the execution model says a name refers to an object. Think of a variable as a label, not a permanently typed box. Assignment evaluates the right side and attaches the name on the left to the resulting object.

```python
trip_distance = 12
print(trip_distance)
print(type(trip_distance))

trip_distance = "twelve miles"
print(trip_distance)
print(type(trip_distance))
```

The name `trip_distance` first refers to an integer and later refers to a string. The object has the type; the name can be rebound. This is Python’s dynamic typing model. You don’t declare a type before assigning a value, although `type()` can show you the object’s current type.

Use names that tell the reader what the value means. PEP 8, Python’s style guide, recommends lowercase names with words separated by underscores, called `snake_case`. `trip_distance` communicates more than `x`, and that clarity matters when a program grows.

## Combine three value categories

Begin with three literal categories. An integer is a whole number such as `7`. A float is a decimal number such as `2.5`. A string is text inside matching single or double quotes, such as `"Ada"`. Digits inside quotes are text, so `"7"` is not the integer `7`.

```python
apples = 4
price = 1.50
label = "apples"

total = apples * price
message = label + ": " + str(apples)

print(total)
print(message)
```

The Python tutorial documents `+`, `-`, `*`, `/`, `//`, `%`, and `**` as the basic arithmetic operators. A slash produces a float; floor division uses `//`; the percent sign gives a remainder; and `**` raises a value to a power. Parentheses make grouping explicit. The same `+` operator joins two strings, but Python won’t add a string and a number without an explicit conversion.

`str(apples)` converts the integer to text so it can be joined to the other strings. You’ll soon use an f-string for the same kind of message with less punctuation.

## Format output with f-strings

PEP 498 introduced formatted string literals, commonly called f-strings. Put `f` before the opening quote, then place a name or small expression inside braces. Python evaluates the expression when it builds the string.

```python
name = "Ada"
steps = 3

summary = f"{name} completed {steps} steps."
print(summary)
print(f"One more step makes {steps + 1} steps.")
```

The braces are placeholders, not printed characters. The result is an ordinary string that `print()` can display. Keep the expressions inside braces small while you’re learning. Calculate a complicated value on its own line, give it a name, and format that name in the f-string.

## Read input, then convert it

The built-in `input()` function displays an optional prompt and returns one line of text. It always returns a `str`, even when you type digits. The Python documentation for `input()`, `int()`, and `float()` makes the conversion step explicit.

```python
name = input("What is your name? ")
age_text = input("How old are you? ")
age = int(age_text)

print(f"Hello, {name}.")
print(f"Next year, you’ll be {age + 1}.")
```

If you type `30`, `age_text` contains the string `"30"`. `int(age_text)` creates the integer `30`, which makes `age + 1` valid. For a decimal value, use the same pattern with `float()`:

```python
height_text = input("Height in metres: ")
height = float(height_text)
print(f"Recorded height: {height} metres")
```

Typing a non-numeric value into either conversion raises `ValueError`. That error is worth noticing, but this chapter’s four named categories are the first navigation map. Later chapters will show how to decide what a program should do after bad input.

## Read a traceback from the bottom up

A traceback is Python’s report of where an error occurred. The Python tutorial recommends starting at the final line for a runtime error: identify the exception name and message, then move upward to the nearest frame in your own file and inspect that line. The caret in a `SyntaxError` marks where Python detected the problem, which can be after the character that caused it.

Here are the four beginner categories you’ll use as first checks:

- **`SyntaxError`**: Python could not parse the program. Check punctuation, quotes, and parentheses near the reported line.
- **`IndentationError`**: the whitespace structure is invalid. Check that a block uses four spaces per level and that statements in one block line up.
- **`NameError`**: Python cannot find a binding for a name. Check spelling and whether you assigned the name before using it.
- **`TypeError`**: an operation or function received an inappropriate type. Check the types on both sides of the operation and convert deliberately when needed.

For example, this script contains a `TypeError` because `input()` returns text:

```python
count_text = input("How many? ")
count = count_text + 1
print(count)
```

The bottom of the traceback says `TypeError` and explains that a string and an integer cannot be combined in that operation. The fix is the conversion pattern you saw earlier:

```python
count_text = input("How many? ")
count = int(count_text) + 1
print(count)
```

The other three categories look different, but the reading habit stays the same. A missing closing quote is a `SyntaxError`; a body with the wrong leading spaces is an `IndentationError`; and a typo such as `nmae` after assigning `name` is a `NameError`. Read the last line first, then inspect your own line and the lines immediately before it.

## Use a small PEP 8 checklist

PEP 8 contains a large set of recommendations. You need a small subset for these first programs: use four spaces for each indentation level, don’t mix tabs and spaces, write names in `snake_case`, and put one space around `=` and arithmetic operators. PEP 8 allows either single or double quotes; consistency within a small example is the useful rule.

```python
first_name = "Ada"
base_score = 8
bonus_score = 2
final_score = base_score + bonus_score

print(f"{first_name}: {final_score}")
```

Formatting doesn’t change what this program calculates. It makes the structure and intent easier to inspect, which helps you locate the errors above.
