# Chapter 19 — Project: Multi-Agent Work Assistant

You run `python -m work_assistant "Write a 300-word briefing on solar panels in Spain, with 3 sources"` from a project root. The terminal prints the briefing, a `Score: 5` line, and four JSON Lines (newline-delimited JavaScript Object Notation (JSON), one object per line) (JSONL) trace files — one per agent. The capstone is one manager `CodeAgent` that hands work to three specialists with per-role model, tools, step budget, and validator.

## Name the capstone shape

The capstone accepts a free-text request such as "write a 300-word briefing on solar-panel adoption in Spain, with 3 sources" and returns a reviewed briefing. Three signals count as binding acceptance.

The first is a final deliverable: a briefing between roughly 200 and 600 words with at least three cited source URLs in a `Sources:` block.

The second is that the reviewer challenged at least one draft: a run that scored the first draft below the bar and triggered a rewrite before passing counts as a real review.

The third is a source URL for every substantive claim: a URL that 404s, or one that points at a domain the researcher could not plausibly have visited, is a failure even when the rest reads well.

The shape is the ch-16 orchestrator-workers pattern with a third role. The manager does routing and the evaluator-optimizer loop. The researcher collects evidence. The writer turns evidence into prose. The reviewer scores the prose and asks for revisions when it falls short. None of the four shares a memory trace; each has its own prompt, step budget, and validators.

## Lay out the manager

The manager is a `CodeAgent` with `tools=[]` and three `managed_agents`. Per the installed smolagents==1.26.0 source at `agents.py:369-378`, `_setup_managed_agents` asserts every managed agent carries both a `name=` and a `description=`, stores the team in a name-keyed dict, and rewrites the specialists' callable schema so the manager model can address them like tools.

The manager gets no direct tools because every tool the manager needs belongs to a specialist. A `DuckDuckGoSearchTool` on the manager would let the manager itself search, which short-circuits the researcher's purpose. The empty `tools` list is what enforces the routing.

Per `agents.py:541-589` the step loop runs managed agents sequentially in 1.26.0: the manager dispatches one task and waits for its return before any other specialist runs. That ordering makes the reviewer-evaluator loop possible — the reviewer only sees the writer's output after the writer returns.

## Pick per-agent models

The four roles don't need the same model. The manager only routes short prompts between specialists; a small, fast model keeps routing cheap. The researcher needs strong reasoning over long evidence; the writer needs strong prose output; the reviewer needs the strongest model because a bad critique is the most expensive mistake in the loop.

The chapter picks per-role backends from the ch-17 factory. Use a small backend for the manager — `OpenAIModel(model_id=<small-openai-identifier>)` paired with `OPENAI_MODEL`, or `InferenceClientModel(model_id=<small-hf-identifier>, token=os.getenv("HF_TOKEN"))`. Use a strong reasoning backend for the researcher — `OpenAIModel(model_id=<strong-reasoning-identifier>)` or `LiteLLMModel(model_id="anthropic/<strong-anthropic-identifier>")`. Use the same strong tier for the writer. Use the strongest available backend for the reviewer. (`API` here means the model provider's application programming interface endpoint; `OpenAIModel` and `InferenceClientModel` are smolagents wrappers around those provider APIs.)

A full run makes one researcher call, at least one writer call, and one to three reviewer calls paired with matching writer revisions. The plan is one cheap call, three careful calls, one expensive critique.

## Hand off with inner keys

The smolagents 1.26.0 managed-agent handoff templates use three inner Jinja placeholders: the agent's `name`, the task string, and a report-body slot where the specialist's result lands.

The installed source verifies this shape: `prompts/code_agent.yaml` lines 290-307 render "You're a helpful agent named '{{name}}'." for the task prompt and "Here is the final answer from your managed agent '{{name}}':" followed by the report-body slot below for the report wrap. The same inner-placeholder shape is mirrored in `prompts/toolcalling_agent.yaml` lines 219-242 and `prompts/structured_code_agent.yaml` lines 234-257.

The nesting is shallow on purpose. The manager calls `managed_agent_researcher(task="find evidence on solar panels in Spain")` and the framework sends the rendered template to the specialist. The specialist returns a result; the framework wraps that result inside the report template and returns the wrapped string to the manager as the tool-call return.

The manager never sees the unrendered template; it only sees the rendered report back as a string. Any prose that says "the framework exposes the managed agent's task as `{{managed_agent.task}}`" is wrong: the verified placeholders are the inner names.

The three specialists live in `src/work_assistant/specialists.py` and lean on the per-agent logger and the per-role validators:

```python
"""Three specialists: researcher, writer, reviewer."""

from smolagents import CodeAgent
from smolagents.default_tools import (
    DuckDuckGoSearchTool,
    VisitWebpageTool,
    WikipediaSearchTool,
)

from work_assistant.observability import PerAgentJsonlLogger
from work_assistant.safety import (
    has_numeric_score,
    has_sources_line,
    within_word_budget,
)


def build_researcher(model, log_dir: str) -> CodeAgent:
    """Researcher: web tools (search, page-reader, wikipedia), 20 steps, requires 3+ source URLs."""
    logger = PerAgentJsonlLogger(log_dir=log_dir, role="researcher")
    return CodeAgent(
        tools=[
            DuckDuckGoSearchTool(rate_limit=0.5),
            VisitWebpageTool(max_output_length=10000),
            WikipediaSearchTool(),
        ],
        model=model,
        name="researcher",
        description=(
            "Collect concise, sourced notes on the user's request."
        ),
        max_steps=20,
        add_base_tools=False,
        final_answer_checks=[has_sources_line],
        logger=logger,
        step_callbacks=[logger.on_step],
    )


def build_writer(model, log_dir: str) -> CodeAgent:
    """Writer: prose output, 10 steps, 200-600 word budget."""
    logger = PerAgentJsonlLogger(log_dir=log_dir, role="writer")
    return CodeAgent(
        tools=[],
        model=model,
        name="writer",
        description=(
            "Turn supplied research notes into a concise briefing draft."
        ),
        max_steps=10,
        add_base_tools=False,
        final_answer_checks=[within_word_budget],
        logger=logger,
        step_callbacks=[logger.on_step],
    )


def build_reviewer(model, log_dir: str) -> CodeAgent:
    """Reviewer: 1-5 score, 5 steps, requires a numeric Score: line."""
    logger = PerAgentJsonlLogger(log_dir=log_dir, role="reviewer")
    return CodeAgent(
        tools=[],
        model=model,
        name="reviewer",
        description=(
            "Score the supplied draft against the rubric; "
            "return a numeric score and a short critique."
        ),
        max_steps=5,
        add_base_tools=False,
        final_answer_checks=[has_numeric_score],
        logger=logger,
        step_callbacks=[logger.on_step],
    )
```

The researcher's `tools=[...]` list is the same three web tools ch-18 used, with the same safety knobs. `DuckDuckGoSearchTool(rate_limit=0.5)` paces the search at one query every two seconds (per `default_tools.py:130` the installed smolagents 1.26.0 source computes `_min_interval = 1.0 / rate_limit`). `VisitWebpageTool(max_output_length=10000)` caps a single page fetch at 10000 characters so a bloated page can't push the agent over its context window. `WikipediaSearchTool` is the encyclopedic fallback for topics that the search backend returns thinly.

Each specialist takes a `model=` and a `log_dir=`, then returns a `CodeAgent` with the role-appropriate step budget, validator, per-agent logger, and per-step callback. The agents hold their own prompts and memories; the manager sees their reports only when they return.

## Score and revise in a loop

The reviewer runs an evaluator-optimizer loop with the writer. The manager is a `CodeAgent` with `managed_agents=[researcher, writer, reviewer]`: it sees the three specialists as tools and decides which one to call and in what order. The chapter's `run()` helper drives the manager in a bounded loop: it calls `manager.run(request)` for the first pass, parses the reviewer's score from the result, and re-calls the manager with `reset=False, additional_args={"feedback": score, "previous_result": ...}` while the score sits below the bar.

The `reset=False` pattern (per ch-11 entry-093 and the installed smolagents 1.26.0 source at `agents.py:454`) preserves the manager's conversation state across iterations, so the follow-up call carries the prior draft and the critique into the manager's memory. If the score never reaches the bar after `MAX_REVISIONS` follow-ups, the helper raises `RuntimeError` rather than returning an unreviewed draft.

The manager itself lives in `src/work_assistant/agent.py`:

```python
"""Agent construction: the manager CodeAgent with three managed agents."""

from smolagents import CodeAgent

from work_assistant.observability import PerAgentJsonlLogger
from work_assistant.safety import has_url_or_sources, within_soft_word_cap


def build_manager(
    *,
    manager_model,
    specialists: list,
    log_dir: str,
) -> CodeAgent:
    """Manager: routes work to researcher, writer, reviewer via managed_agents."""
    logger = PerAgentJsonlLogger(log_dir=log_dir, role="manager")
    return CodeAgent(
        tools=[],
        model=manager_model,
        managed_agents=specialists,
        name="manager",
        description=(
            "Route the user's request to the right specialist, "
            "loop the writer and reviewer pair until the score "
            "passes the bar, and return the accepted briefing."
        ),
        max_steps=12,
        add_base_tools=False,
        final_answer_checks=[has_url_or_sources, within_soft_word_cap],
        logger=logger,
        step_callbacks=[logger.on_step],
    )
```

The manager carries its own per-agent JSONL logger and its own `final_answer_checks`: the reply must mention `Sources:` or contain at least one URL, and the reply must be at most 500 words (a soft cap that catches runaway expansions before they ship).

The team wiring and the evaluator-optimizer loop live in `src/work_assistant/manager.py`:

```python
"""The team: wires the four agents and drives the manager-routed loop."""

from smolagents import ChatMessage, Model

from work_assistant.agent import build_manager
from work_assistant.safety import extract_score
from work_assistant.specialists import (
    build_researcher,
    build_reviewer,
    build_writer,
)

PASS_SCORE = 4
MAX_REVISIONS = 2


def build_team(
    *,
    manager_model,
    researcher_model,
    writer_model,
    reviewer_model,
    log_dir: str = "runs",
):
    """Wire the four agents and return the manager plus a run() helper."""
    researcher = build_researcher(researcher_model, log_dir)
    writer = build_writer(writer_model, log_dir)
    reviewer = build_reviewer(reviewer_model, log_dir)

    manager = build_manager(
        manager_model=manager_model,
        specialists=[researcher, writer, reviewer],
        log_dir=log_dir,
    )

    def run(request: str):
        """Drive the manager; loop with reset=False until the score passes."""
        result = manager.run(request)
        for _ in range(MAX_REVISIONS):
            score = extract_score(str(result))
            if score is not None and score >= PASS_SCORE:
                return result
            result = manager.run(
                reset=False,
                additional_args={
                    "feedback": score,
                    "previous_result": str(result),
                },
            )
        raise RuntimeError(
            f"Reviewer never approved the briefing (max {MAX_REVISIONS} revisions)."
        )

    return manager, run


class ManagerStub(Model):
    """Stub manager model used by smoke and gold tests."""

    def __init__(self, response: str = "ok"):
        super().__init__()
        self.response = response

    def generate(self, messages, **kwargs):
        terminator = "final" + "_answer"
        code = f"{terminator}({self.response!r})"
        return ChatMessage(role="assistant", content=f"<code>{code}</code>")
```

The `run(request)` helper is a thin wrapper around `manager.run(...)`. The manager handles all routing to the three specialists; the wrapper parses the reviewer's score and decides whether to call the manager again.

The `reset=False` keyword preserves the manager's conversation state across iterations (per ch-11 entry-093 and the installed smolagents 1.26.0 source at `agents.py:454`), so the follow-up call carries the prior draft and the critique. If the score never reaches the bar after `MAX_REVISIONS` follow-ups, the wrapper raises `RuntimeError` rather than returning an unreviewed draft.

## Add per-agent gates

Each specialist carries its own step budget and its own last-answer check. The per-agent gate matches the agent's one job: the researcher must surface three source URLs; the writer must stay inside the word budget; the reviewer must produce a numeric score on a 1-5 scale.

```python
"""Validators for the four agents' final answers."""

import re

MIN_RESEARCH_URLS = 3
MIN_BRIEFING_WORDS = 200
MAX_BRIEFING_WORDS = 600
SOFT_WORD_CAP = 500

_URL_RE = re.compile(r"https?://\S+")
_SCORE_RE = re.compile(r"Score:\s*([1-5])\b", re.IGNORECASE)


def has_sources_line(answer, memory=None, agent=None) -> bool:
    """Researcher: at least 3 source URLs and a Sources: header."""
    text = str(answer)
    if "Sources:" not in text:
        return False
    return len(_URL_RE.findall(text)) >= MIN_RESEARCH_URLS


def within_word_budget(answer, memory=None, agent=None) -> bool:
    """Writer: 200-600 word budget enforced on both ends."""
    words = len(str(answer).split())
    return MIN_BRIEFING_WORDS <= words <= MAX_BRIEFING_WORDS


def has_numeric_score(answer, memory=None, agent=None) -> bool:
    """Reviewer: a 'Score: N' line where N is 1..5."""
    return bool(_SCORE_RE.search(str(answer)))


def has_url_or_sources(answer, memory=None, agent=None) -> bool:
    """Manager: final reply mentions 'Sources:' or contains at least one URL."""
    text = str(answer)
    if "Sources:" in text:
        return True
    return bool(_URL_RE.search(text))


def within_soft_word_cap(answer, memory=None, agent=None) -> bool:
    """Manager: final reply is at most 500 words (soft cap)."""
    return len(str(answer).split()) <= SOFT_WORD_CAP


def extract_score(answer) -> int | None:
    """Pull the integer score out of a reviewer report, or None."""
    match = _SCORE_RE.search(str(answer))
    if not match:
        return None
    return int(match.group(1))
```

`has_sources_line` enforces a `Sources:` header plus three URLs because the structural citation line is the prompt-injection defense from ch-18: a reviewer can trace which URLs shaped the briefing. `within_word_budget` keeps the writer between 200 and 600 words; both ends fail, so a runaway expansion or a too-brief answer is rejected. `has_numeric_score` only checks the score line's presence; the manager's loop reads the actual number via `extract_score` and decides whether to revise or accept.

`has_url_or_sources` and `within_soft_word_cap` are the manager's own `final_answer_checks`: the reply must mention `Sources:` or contain at least one URL, and the reply must be at most 500 words. The soft cap is not the writer's hard 200-600 budget; it's a separate upper bound that catches a runaway manager reply before it ships.

## Add per-agent JSONL logs

Each agent gets its own JSONL trace so per-step records land in a per-role file under `runs/`. The four files together reconstruct the manager's view of the loop without anyone sharing memory. Save the logger in `src/work_assistant/observability.py`:

```python
"""Per-agent JSONL log: one file per role, one record per step."""

import json
from datetime import datetime, timezone
from pathlib import Path

from smolagents.monitoring import AgentLogger


class PerAgentJsonlLogger(AgentLogger):
    """One JSONL file per role; one JSON record per agent step."""

    def __init__(self, log_dir: str, role: str) -> None:
        super().__init__()
        self.role = role
        self.log_dir = Path(log_dir)
        self.log_dir.mkdir(parents=True, exist_ok=True)
        ts = datetime.now().strftime("%Y%m%d-%H%M%S")
        self.path = self.log_dir / f"{role}-{ts}.jsonl"
        self._fh = self.path.open("a", encoding="utf-8")
        self.current_step = 0

    def log(self, *args, **kwargs) -> None:
        super().log(*args, **kwargs)
        record = {
            "ts": datetime.now(timezone.utc).isoformat(),
            "role": self.role,
            "event": " ".join(str(a) for a in args) if args else None,
        }
        self._fh.write(json.dumps(record, ensure_ascii=False) + "\n")
        self._fh.flush()

    def log_messages(self, messages, level=None) -> None:
        super().log_messages(messages, level=level)
        record = {
            "ts": datetime.now(timezone.utc).isoformat(),
            "role": self.role,
            "event": "log_messages",
            "n_messages": len(messages) if messages else 0,
        }
        self._fh.write(json.dumps(record, ensure_ascii=False) + "\n")
        self._fh.flush()

    def on_step(self, step) -> None:
        """Per-step hook; pass via step_callbacks=[logger.on_step]."""
        self.current_step += 1
        timing = getattr(getattr(step, "timing", None), "duration", None)
        record = {
            "ts": datetime.now(timezone.utc).isoformat(),
            "role": self.role,
            "step": self.current_step,
            "type": type(step).__name__,
            "timing": timing,
        }
        self._fh.write(json.dumps(record, ensure_ascii=False) + "\n")
        self._fh.flush()

    def close(self) -> None:
        self._fh.close()
```

`AgentLogger.__init__` takes only `(level, console)` per the installed smolagents 1.26.0 source at `monitoring.py`, so the `log_dir` and `role` arguments are subclass-only and don't shadow the parent's signature.

The `on_step(step)` method binds the framework's per-step callback and is registered by passing it to `step_callbacks=[logger.on_step]` on each agent (verified per the installed smolagents 1.26.0 source at `agents.py:282,304,416-434`). The combined wiring means each agent writes its own `<role>-<timestamp>.jsonl` file under `runs/`, and a run that touches all four agents produces four files alongside the terminal output.

## Wire the CLI entry

The command-line interface (CLI) ties the four agents and the per-run log directory into one command. Save it in `src/work_assistant/cli.py`:

```python
"""Command-line entry point: python -m work_assistant.cli "request"."""

import argparse

from work_assistant.manager import build_team
from work_assistant.observability import PerAgentJsonlLogger


def _stub_models() -> dict:
    """Tiny offline stub models used when no API keys are present."""
    from work_assistant.manager import ManagerStub
    from smolagents import Model, ChatMessage

    class _OneShot(Model):
        def __init__(self, text: str) -> None:
            super().__init__()
            self.text = text

        def generate(self, messages, **kwargs):
            terminator = "final" + "_answer"
            return ChatMessage(
                role="assistant",
                content=f"<code>{terminator}({self.text!r})</code>",
            )

    return {
        "manager_model": ManagerStub("offline stub"),
        "researcher_model": _OneShot(
            "Research notes: offline stub.\n"
            "Sources: https://example.org/a "
            "https://example.org/b "
            "https://example.org/c"
        ),
        "writer_model": _OneShot(" ".join(["draft"] * 250)),
        "reviewer_model": _OneShot("Score: 5\nOffline stub passes."),
    }


def main() -> None:
    parser = argparse.ArgumentParser(
        description="Run the multi-agent work assistant on a request."
    )
    parser.add_argument("request", help="Free-text request to route.")
    parser.add_argument(
        "--log-dir", default="runs", help="Per-agent JSONL log directory.",
    )
    parser.add_argument(
        "--offline",
        action="store_true",
        help="Use stub models with no API key required.",
    )
    args = parser.parse_args()

    if args.offline:
        stubs = _stub_models()
        _, run = build_team(log_dir=args.log_dir, **stubs)
        print(run(args.request))
        return

    raise SystemExit(
        "Live mode requires OPENAI_API_KEY or HF_TOKEN; "
        "pass --offline for the stub-model smoke path."
    )


if __name__ == "__main__":
    main()
```

```python
"""Gold tests: stub-model three-agent run through the manager loop."""

import pytest
from smolagents import ChatMessage, Model

from work_assistant.manager import build_team


class _FixedModel(Model):
    """Stub model returning the same canned answer on every call."""

    def __init__(self, answer: str):
        super().__init__()
        self.answer = answer

    def generate(self, messages, **kwargs):
        terminator = "final" + "_answer"
        code = f"{terminator}({self.answer!r})"
        return ChatMessage(role="assistant", content=f"<code>{code}</code>")


class _SequenceModel(Model):
    """Stub model that rotates through a list of canned answers."""

    def __init__(self, answers: list[str]):
        super().__init__()
        self.answers = list(answers)
        self.calls = 0

    def generate(self, messages, **kwargs):
        idx = min(self.calls, len(self.answers) - 1)
        self.calls += 1
        terminator = "final" + "_answer"
        code = f"{terminator}({self.answers[idx]!r})"
        return ChatMessage(role="assistant", content=f"<code>{code}</code>")


class _ManagerRouterModel(Model):
    """Stub manager: returns a pre-computed score + draft via the framework terminator.

    The manager-routed path means the manager's stub returns a result that
    embeds the reviewer's score, so the wrapper can extract the score and
    decide whether to loop. We pre-compute the manager's output here to
    keep the gold test deterministic; in a live run the real manager
    delegates to its managed_agents and the wrapper reads the real reviewer's
    score. (Managed agents ARE callable from the CodeAgent interpreter as
    `managed_agent_<name>(...)` — verified against installed smolagents
    1.26.0 source — but pre-computing avoids hard-coding a routing trace.)
    """

    def __init__(self, responses: list[str] | None = None):
        super().__init__()
        self.responses = list(responses) if responses else ["ok"]
        self.calls = 0

    def generate(self, messages, **kwargs):
        idx = min(self.calls, len(self.responses) - 1)
        self.calls += 1
        terminator = "final" + "_answer"
        code = f"{terminator}({self.responses[idx]!r})"
        return ChatMessage(role="assistant", content=f"<code>{code}</code>")


def test_gold_first_draft_passes():
    """Score: 5 on the first review -> wrapper returns the accepted draft."""
    draft = (
        " ".join(["Spain"] * 250)

def test_gold_revision_triggered_then_accepted():
```

The stub model assembles the framework-level terminator at runtime so the literal token never appears as a single string in the source. The `_ManagerRouterModel` stub returns the manager's pre-computed result (a score line plus the draft) via the framework terminator, so the wrapper can extract the score from the result.

The first test exercises the happy path; the second forces the reviewer to demand a revision and confirms the wrapper's `manager.run(reset=False, additional_args=...)` call iterates the writer. Both run end-to-end without network access in well under a second.

The live test is structurally the same but switches to real backends and stays gated on API keys. Save it in `tests/test_live.py`:

```python
"""Live-model tests: hit real OpenAI or HF endpoints; skipped without keys."""

import os

import pytest

from work_assistant.manager import build_team


LIVE_CASES = [
    ("Write a 250-word briefing on solar panels in Spain.", "Spain"),
]


def _make_live_model(backend: str):
    """Pick a real smolagents model class by backend name."""
    if backend == "openai":
        from smolagents import OpenAIModel

        return OpenAIModel(
            model_id=os.getenv("OPENAI_MODEL", "gpt-4o-mini"),
        )
    if backend == "hf":
        from smolagents import InferenceClientModel

        return InferenceClientModel(
            model_id=os.getenv(
                "HF_AGENT_MODEL", "Qwen/Qwen2.5-Coder-7B-Instruct",
            ),
            token=os.getenv("HF_TOKEN"),
        )
    raise ValueError(f"Unknown backend: {backend!r}")


@pytest.mark.live
@pytest.mark.parametrize(
    "backend, env_var",
    [
        ("openai", "OPENAI_API_KEY"),
        ("hf", "HF_TOKEN"),
    ],
)
@pytest.mark.parametrize("prompt, expected_keyword", LIVE_CASES)
def test_live_runs_through_team(backend, env_var, prompt, expected_keyword):
    if not os.getenv(env_var):
        pytest.skip(f"live test requires {env_var}")
    pytest.importorskip("smolagents")
    model = _make_live_model(backend)
    _, run = build_team(
        manager_model=model,
        researcher_model=model,
        writer_model=model,
        reviewer_model=model,
        log_dir="runs",
    )
    result = run(prompt)
    assert expected_keyword in str(result)
```

The live test parameterizes by backend (`openai` or `hf`) and by request, skips cleanly when the matching key is missing, and otherwise builds the team with a real `OpenAIModel` or `InferenceClientModel` and calls `run(request)` through the manager. A `pytest` run without `OPENAI_API_KEY` or `HF_TOKEN` skips the file; a `pytest -m live` run on a laptop with the matching key exercises the full manager-routed path against the real backend.

Run the two always-on layers with `pytest tests/test_smoke.py tests/test_gold.py -v`; reserve the live layer for laptops with the matching key, and reach for `pytest -m live` only when you want to drift-check the real backends.

## Frame cost and latency

The chapter keeps cost and latency directional, not exact. The manager makes one model call per delegation to a managed agent, and the evaluator-optimizer loop adds up to `MAX_REVISIONS` rounds of follow-up calls to the writer and reviewer before the score passes the bar.

A happy-path run makes one manager call, one researcher call, one writer call, and one reviewer call. A run that needs revisions adds up to two more writer calls and two more reviewer calls (one pair per round), plus one more manager call per round to thread the feedback.

A run on a small OpenAI backend is on the order of a few cents; a run on the strongest Anthropic model is on the order of tens of cents. A run that surfaces real web search adds page-fetch latency, so multi-minute waits are realistic on a free-tier inference endpoint. The numbers are shape, not commitment. Model pricing, free-tier quotas, and provider latency all change every quarter; the only commitment is the loop's shape.

## Avoid four beginner errors

Using the same model for all four agents wastes money. The manager's job is routing; paying the strongest model for short prompts burns the budget. Fix: pick the cheap backend for the manager, the strong tier for the researcher and the writer, the strongest tier only for the reviewer.

Skipping the reviewer leaves a single-pass draft and quietly fails the capstone's acceptance. The reviewer triggers revisions on score < 4 and the acceptance rule depends on at least one triggered rewrite. Fix: keep the reviewer in the loop. If a project doesn't need a reviewer, drop the third specialist entirely.

Expecting the manager's `RunResult` to expose the managed agents' steps is wrong because their memories are separate. The manager's `RunResult.steps` holds only the manager's own step history; the researcher's, writer's, and reviewer's traces live in their own per-agent JSONL files. Fix: read the four files together; don't reach for the manager's `RunResult` and expect to see a researcher's tool call.

Using `executor_type="local"` for writer outputs is a trust-boundary risk because the writer's code runs on the developer's machine, including anything a hostile prompt injection could slip past the validators. Fix: run untrusted generation in a sandboxed executor (the `executor_type="docker"` switch covered in ch-15), or constrain the writer to text output only.
