# Chapter 4 — Make Programs Decide and Repeat

Your terminal shows a prompt, but the program can't yet react to what you type. In this chapter, you'll give it choices and repetition. You'll use conditions to select one path, loops to revisit work, and a short error map to stop repeated work from becoming repeated trouble.



## Turn values into yes-or-no decisions

A Boolean, written `bool` in Python, has one of two values: `True` or `False`. Comparisons produce Booleans, and conditions use them to decide whether a block of code runs.

Python also tests the truthiness of other values. The false values you'll meet are `None`, `False`, numeric zero (`0`, `0.0`, or `0j`), and empty values: `""`, `()`, `[]`, `{}`, `set()`, and `range(0)`. Other values are truthy. This lets `if name:` mean "run this block when `name` isn't an empty string."

```python
name = "Ada"

if name:
    print(f"Hello, {name}.")
```

The shortcut reads cleanly when emptiness is the real question. When you need a strict Boolean value for storage or output, call `bool(name)` rather than relying on an object being truthy.

## Compare values

Six comparison operators cover the beginner cases: `==` means equal, `!=` means not equal, `<` means less than, `<=` means less than or equal, `>` means greater than, and `>=` means greater than or equal. A comparison asks a question and returns `True` or `False`.

```python
score = 82

print(score == 82)
print(score != 50)
print(score < 90)
print(score <= 82)
print(score > 70)
print(score >= 82)
print(0 <= score <= 100)
```

The final line is a chained comparison. Python reads `0 <= score <= 100` as two linked checks, evaluating whether the score is at least zero and at most one hundred. Chaining keeps a range check close to the mathematical form you already know.

Use `==` for value comparison. A single `=` performs assignment: it binds a name to a value. That difference matters because `if score = 82:` is invalid syntax, while `if score == 82:` asks the intended question.

## Combine conditions without evaluating everything

The operators `and`, `or`, and `not` combine conditions. `and` needs both sides to be truthy, `or` needs at least one truthy side, and `not` reverses the truth value.

`and` and `or` short-circuit. Python evaluates the right side of `and` only when the left side is truthy, and it evaluates the right side of `or` only when the left side is falsey. The division below never runs because `denominator != 0` is already false.

```python
denominator = 0
safe_to_divide = denominator != 0 and 10 / denominator > 1
typed_name = ""
display_name = typed_name or "Guest"

print(safe_to_divide)
print(display_name)
print(not display_name == "Admin")
```

There is a trap in the second result. `and` and `or` return one of their operands, not a forced Boolean. Here, `typed_name or "Guest"` returns the string `"Guest"`. Wrap an expression in `bool(...)` when later code requires exactly `True` or `False`. `not` does return a Boolean, and `not a == b` means `not (a == b)`.

## Choose one branch

An `if` statement selects one block. Each `elif`, short for "else if," offers another condition when earlier conditions were false. The optional `else` runs when no earlier condition was truthy. Python evaluates the headers from top to bottom and runs only the first matching body.

```python
score = 82

if score >= 90:
    result = "high"
elif score >= 70:
    result = "middle"
else:
    result = "low"

print(result)
```

Every header ends with a colon. Three indentation rules keep the structure visible. First, the body is indented four spaces farther than the header. Second, every statement in that body lines up at the same depth. Third, the block stays at that deeper level until the next line returns to the earlier level. Don't mix tabs and spaces.

## Repeat while a condition remains true

A `while` loop tests its condition before every repetition. If the condition starts false, the body doesn't run. If it stays true, the body keeps running, so the body usually changes a value used by the condition.

```python
count = 0

# Infinite loop if the update below is removed.
while count < 3:
    print(count)
    count += 1
```

This example names the infinite-loop error in place. Without `count += 1`, `count < 3` never changes. The one-line fix is to update the value that controls the condition, or to use an explicit stopping test with `break`.

## Stop or skip a repetition

`break` ends the innermost loop immediately. `continue` skips the remaining lines in the current repetition and returns to the loop's next test. Both statements must appear inside a `while` or `for` loop; using either at the top level raises `SyntaxError`.

```python
attempt = 0

while True:
    attempt += 1

    if attempt == 2:
        continue

    print(f"Checking attempt {attempt}")

    if attempt == 3:
        break
```

`while True:` makes the repetition deliberate, while the `break` names the exit. This pattern is useful when you can't express the stopping condition until partway through the body. Check that at least one reachable path leads to `break`.

## Visit each item with `for`

A `for` loop takes items from a sequence in order and binds the loop variable to each item. Iterating means visiting those items one at a time. A string supplies characters, while a list supplies its stored values.

```python
for letter in "agent":
    print(letter)

names = ["Ada", "Lin"]
for name in names:
    print(f"Hello, {name}.")
```

Don't add or remove items from the same collection while iterating over it. Positions can shift and cause items to be skipped. Iterate over a copy, such as `for name in names.copy():`, or build a new collection instead. Ch-05 will give collections a full treatment.

## Count with half-open ranges

Use `range()` when a loop needs a sequence of integers. `range(stop)` starts at zero, `range(start, stop)` chooses the first value, and `range(start, stop, step)` also chooses the distance between values. A negative step counts downward.

```python
for number in range(5):
    print(number)

for number in range(2, 5):
    print(number)

for number in range(10, 0, -2):
    print(number)
```

Every form is half-open: the start can appear, but the stop never does. `range(5)` produces `0` through `4`, and `range(2, 5)` produces `2`, `3`, and `4`. This rule explains many off-by-one errors. A step of zero raises `ValueError` because the sequence couldn't advance.

## Name the four control-flow errors

Keep these four fingerprints near your first loop programs:

- **Infinite loop:** the `while` condition never becomes false. Fix it by updating the controlling value or reaching a `break`.
- **Off-by-one:** the loop runs once too many or once too few. Fix it by remembering that a `range()` stop is excluded and checking `<` versus `<=`.
- **`=` versus `==`:** assignment appears where a comparison belongs. Fix `if score = 82:` by writing `if score == 82:`.
- **Mutating during iteration:** a loop changes the collection it is visiting. Fix it by iterating over a copy or building a new collection.

These names turn a vague "the loop is wrong" feeling into four concrete checks. Start with the loop's stopping condition, then inspect its bounds, comparisons, and collection changes.

## Check: decide and repeat in one script

Run this with the interpreter from your `.venv`. The `assert` stays silent when the loop visits all three tasks and raises `AssertionError` if the final position is wrong.

```python
tasks = ["read", "test", "report"]
position = 0

while position < len(tasks):
    task = tasks[position]

    if task == "test":
        print("Run the test")
    else:
        print(f"Do: {task}")

    position += 1

for number in range(1, 4):
    print(f"Pass {number}")

assert position == 3
```

Expected output:

```text
Do: read
Run the test
Do: report
Pass 1
Pass 2
Pass 3
```
