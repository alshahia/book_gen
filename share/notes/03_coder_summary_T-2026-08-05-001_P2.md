## Deviations from plan
- **Tokenizer helpers are full copies, not imports.** Spec mandates this for script independence — followed. The helpers are byte-for-byte identical to the corresponding block in `book_check.py` so behavior matches.
- **Tests use direct function calls, not subprocess.** Plan said "all should be file-based (not mocks)". I interpreted "file-based" as "real fixture chapters (not stubs)" rather than "must spawn a subprocess". Direct calls: (a) avoid the Python 3.14 + Windows subprocess handle flakiness that the kit's other tests already exhibit, (b) run ~70× faster (0.07s vs ~1s), (c) make failures easier to diagnose (no JSON parsing layer). One reviewer concern this raises: argparse + `--json` + `main()` entry point is not directly exercised in the test suite. **Mitigation**: I manually ran the script as a subprocess on `books/daily-focus/` (above) and verified the JSON envelope shape matches what `main()` produces. A future hardening pass could add a single subprocess smoke test once the kit's subprocess issue is fixed.
- **`_force_utf8_stdio()` helper added at the start of `main()`.** Windows detects cp1256 for stdout when Python files contain Arabic content (the source of this script contains plenty), so `json.dump` chokes on `≤` / `«»` etc. when piping the JSON to another tool. Reconfiguring stdout/stderr to UTF-8 up-front fixes it cleanly without touching every print statement. One reviewer concern: reconfigure is a no-op on Linux/macOS where utf-8 is the default, so the helper is a defensive belt-and-suspenders.
- **Default `Beat window` is (600, 750) per spec.** This is per-chapter-window convention applied to per-beat; for a 25-page English nonfiction chapter like `daily-focus/ch-01.md` it will FAIL most beats (each H2 is ~150-330 words, way below 600). The plan's spec says "default 600-750"; I followed it. A real-world waiver for that book: pass a custom `--config` style-guide with `Beat window: 100 - 500` in frontmatter. Called out in `Self-critique` below.
- **`dialogue_own_line` strips trailing punctuation after the quoted span.** A line `«text».` (dialogue only, ending with the closing quote + a period) is NOT a violation; a line `The man said «hello» then left.` IS. My initial implementation treated both as violations; refined to strip ` \t\r\n.!?،؟,;:;` after the quoted span before checking for residual text. Spec didn't explicitly call out this edge case — needed for Arabic-style sentence-end quotes.
- **`countdown` skips chapters without a `ch-NN` filename (e.g. `introduction.md`).** Spec says "only run when chapter number ≥ applies_from"; chapters like `introduction` have no number, so the check has no answer. I emit PASS with skip-evidence rather than FAIL.
- **`_chapter_label(chapter_path)` returns the chapter stem (`ch-NN`).** Used as the JSON `chapter` key + the markdown report's filename. Renamed internally to avoid collision with the `chapter` positional arg.

## Known issues / TODOs left in code

Out of scope for P2 — call out for a future hardening pass (consider `subprocess.run(..., creationflags=CREATE_NO_WINDOW)` or running tests via `-p no:cacheprovider` to avoid handle-pressure accumulation).

- **Arabic punctuation rule excludes period (` .`).** A line containing only periods is too common in technical text (table separators etc.) to flag. The cost: authors who mix Arabic + English decimals (`3.14`) won't be flagged. The window is `" - " + Arabic decimal replacement is left to P10 (LanguageTool)`. Not in scope.
- **`dialogue_own_line` line-level scan is O(n_lines × n_quotes).** Fine for any chapter a human would write (~10k lines max). If the chapter is auto-generated with thousands of inline quotes, this becomes O(n²). Not a real concern for the use case.
- **`sentence_length` regex ignores Abjad letter Han/aa/etc boundaries.** A sentence in classical Arabic with no `،` / `.` / `؟` joins everything into one. Same for English sentences with no terminal punctuation. The 3-sentence minimum guards against `len(sents) < 3 → PASS` hiding single-sentence chapters. Acceptable for now.
