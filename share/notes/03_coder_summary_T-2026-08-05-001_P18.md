## Deviations from plan
- **DB path policy:** the plan says "DB path = `BOOK_KG_DB` env var (default: `.book-kg.db` in current dir)" for the FastMCP server. The CLI `indexer.py` accepts a positional `book` plus an optional `--db`, defaulting to `<book>/.book-kg.db` so the indexer is callable from anywhere without env-var wiring. The query module honors the env var default; the FastMCP server reads the same env var. Both behaviors are within spec.
- **Index book count for daily-focus smoke:** the daily-focus bible has no `## Motifs` / `## Characters` tables and no `frozen-lines.json`, so the real-world smoke returns motif_count=0, character_count=0, frozen_line_count=0. The 3-chapter fixture (kg-3ch-book) DOES populate them and is what the tests exercise. The deviation is environmental, not a code bug; documented in the summary.
- **UTF-8 stdio force:** the spec asks for it at the top of `server.py`, `indexer.py`, and `query.py`. All three files have the reconfigure block at lines 1-7 (BEFORE any other import). Confirmed via `head -10`.
- **Path validation:** the indexer uses `resolve_under()` for every chapter file. The query module validates `ch-NN` shape with a strict regex on user input. The FastMCP server adds no shell — every tool call is a direct Python function call.
- **No new dependencies in `opencode.jsonc`:** FastMCP is not installed in this environment; the server imports defensively (the module loads even when `fastmcp` is absent). The MCP `book-kg` entry is wired as a local command that invokes `py book-kit/mcp/book-kg/server.py`, matching the host pattern used by `browsermcp` and `cocoindex-code`. When the user installs `fastmcp` (`pip install fastmcp`), the four tools become available to any agent with the MCP enabled.

## Known issues / TODOs left in code
- P18 is the only phase that requires a new pip package (`fastmcp`); the install command belongs to a future housekeeping pass once the user opts in. The server module ships a clean error message when FastMCP is missing.
- The indexer's `bible.md` parser reads `## Continuity anchor` / `## Motifs` / `## Characters` sections. The continuity-anchor scope parser only accepts `ch-NN..ch-NN` and `ch-NN-ch-NN` ranges; if a writer hand-codes `chapters ch-NN through ch-NN` the parser will miss the row. Defensive future hardening, not a real-world bug.
- `contradicts()` currently joins frozen-line occurrences with `continuity_anchors` on `book_id` only. A future tightening should match anchor keyword to frozen-line quote for a less noisy cross-reference. The interface (returns a list of dicts) makes that a one-query swap.
- `references()` filters on `tc.chapter_num=`. The interface does not currently distinguish "the source row came from `cross_ref.py` rather than a `ch-NN` literal in the source." Defensive future hardening.
