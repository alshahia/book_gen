## Phase 3 — Memory validator (`scripts/validate-memory.sh`)

**Goal:** Ship the frontmatter + lifecycle validator. Per locked design #8, this is REQUIRED in v0.13.0 (not optional).

**Deliverables:**
- `scripts/validate-memory.sh` — ~50 LOC bash, executable (`chmod +x`).
  - Walks all `*.md` files under `agents_manager/memory/{global,projects}/` and `agents_manager/<role>/notes/{semantic,episodic}/`.
  - For each: checks frontmatter (first line `---`, closing `---`).
  - Required keys: `scope`, `topic`, `status`, `created`, `last_verified`.
  - `scope` ∈ {global, project, role}; `status` ∈ {active, superseded}.
  - `created` and `last_verified` parse as YYYY-MM-DD.
  - When `status: superseded`, `superseded_by:` is present AND points to a file that exists.
  - Optional mode: `--secrets-strict` (exits non-zero if any body line matches `02_secrets_`).
  - Exit code: 0 = no issues; 1 = at least one issue.
- Dry-run verification:
  - Empty scaffold run → exit 0.
  - Sample valid entry run → exit 0.
  - Sample broken entry run (`status: superseded` + missing `superseded_by:`) → exit 1 with clear stderr.
  - All sample entries deleted after verification (no content backfill per non-goal).

**Tasks:** see `tasks/T-2026-07-03-002.md` rows P3T1..P3T2.

**Done when:**
1. `test -x scripts/validate-memory.sh` is true (executable bit set).
2. `bash scripts/validate-memory.sh` exits 0 on the empty scaffold (proves the script handles "no files" gracefully).
3. Validation harness (run by am-coder during this phase, NOT shipped to repo): a sample broken entry produces exit code 1 with stderr line count ≥1.
4. `shellcheck scripts/validate-memory.sh` (if shellcheck available) reports 0 warnings; otherwise `bash -n scripts/validate-memory.sh` parses cleanly.
5. `git status --short` shows ONLY 1 new path (`scripts/validate-memory.sh`), no modifications.
