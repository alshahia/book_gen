project into either (A) a reusable template at `templates/<name>/` or (B)

## Approach

**Authoring-side first, integration-side second.** Phase 3 splits into two
sub-phases with a clean dependency seam: sub-phase 3.1 produces the four new
files plus a one-subsection cross-ref in `templates/CONTRIBUTING.md`; sub-phase
3.2 then modifies the two existing rulebooks (`agents_manager/memory/README.md`
+ `agents_manager/SKILL.md`) that need to know what the new skill does. This
order matters because P3T3 and P3T4 reference paths/fields established by P3T1
+ P3T2 — flipping the order leaves 3.2 tasks editing files before their
dependencies exist on disk.

**The 4 new files are the capability itself.** `templates/EXTRACTION.md` is the
rulebook (mirrors `AUTHORING.md` style: TL;DR, 8-rule discipline, folder
shape, pre-flight checklist, worked example, "what the agent can't decide"
section, cross-refs). `agents_manager/extract/SKILL.md` is the loadable skill
with YAML trigger frontmatter per Anthropic Skills convention
(`description:` containing the trigger phrases + `paths:` listing write
destinations + body describing the procedure). `agents_manager/extract/rules.md`
carries 8 numbered hard rules (R1 no `templates/<name>/memory/` writes from
this lane; R2 no secrets; R3 LICENSE with attribution; R4 always invoke
`tests/verify.sh`; R5 always run `scripts/validate-memory.sh`; R6 never
auto-default to `global/`; R7 never overwrite, suffix on collision; R8 always
emit audit log). `agents_manager/memory/.extract-config.yaml.example` is the
opt-in flag pattern (gitignored in production; example checked in).

**The 3 modifications wire the capability into existing rulebooks.**
`agents_manager/memory/README.md` line 62 gains `tech_stack:` + `domain:` in
the required-frontmatter list (comma-separated); the read-on-entry protocol
gains a soft-filter step (specialist judgment, not hard gate). `agents_manager/SKILL.md`
Phase 5b menu (lines 406-412) gets option 5 "Extract to template / core
knowledge," gated on the opt-in flag read from
`agents_manager/memory/.extract-config.yaml`. `templates/CONTRIBUTING.md` gains
a "via extract" subsection pointing at the new skill, as a sibling path to
the existing "I want to add a new template" flow.

**Memory written:** none this dispatch. The plan itself is the artifact; no
durable cross-task insight emerged that wasn't already in
`agents_manager/research/notes/semantic/extract-feature-framing-vs-existing-protocol.md`
(operations angle wrote that one). No new entry needed.

## Risks acknowledged

Lifted from the merged research `share/notes/01_research_T-2026-07-04-009.md`
F8 (5 HIGH / 4 MEDIUM / 3 LOW, deduped). Each maps to a concrete mitigation in
the plan.

- **R1 (HIGH, soft-wall erosion)** — covered by the lane design itself:
  `extract/SKILL.md` + `extract/rules.md` form a soft-skill without a roster
  slot; no other specialist's SKILL.md gets amended. Master edits its own
  SKILL.md only via the explicit maintenance task P3T4.
- **R2 (HIGH, IP/license contamination)** — encoded in `extract/rules.md` R3
  (no LICENSE without attribution, refuse if unattributed) + `EXTRACTION.md`
  pre-flight checklist (license-scan first; user must declare LICENSE
  inheritance). Forward-looking gate: every future extraction passes through
  this gate before any write.
- **R3 (HIGH, secrets exfiltration)** — `extract/rules.md` R2 (refuse and
  surface if pre-flight hits; secrets denylist: `.env*`, `*.pem`, `*.key`,
  `id_rsa*`, `02_secrets_*`, plus `sk-[A-Za-z0-9]{20,}` regex).
- **R4 (HIGH, capability overlap / authoring-standard drift)** — `EXTRACTION.md`
  is a sibling to `AUTHORING.md`, not a replacement. Output must pass
  `tests/verify.sh` (encoded in `extract/rules.md` R4); Rule 8 acceptance
  checklist applies unchanged.
- **R5 (HIGH, UX framing mismatch)** — `EXTRACTION.md` documents honestly:
  "scaffold a starter template (~30s — fills placeholders only; complete the
  9-step recipe in `templates/AUTHORING.md` afterwards)." Mirrors the
  operations angle R2 mitigation verbatim.
- **R6 (MEDIUM, source has open WARNs)** — encoded in `extract/rules.md` and
  am-review FAIL condition F8: refuse if source's `04_warns_register_*.md` has
  OPEN entries; user must explicitly accept propagation.
- **R7 (MEDIUM, memory cross-pollination)** — encoded in `extract/rules.md` R6
  (never auto-default to `global/`, require user-confirmed scope per entry) +
  memory README schema adding `tech_stack:`/`domain:` so cross-project writes
  can be filtered on read.
- **R8 (MEDIUM, duplicate templates)** — encoded in `EXTRACTION.md` pre-flight:
  Jaccard >0.6 with existing `templates/<name>/` → refuse and surface
  "promote via CONTRIBUTING.md instead."
- **R9 (MEDIUM, license of source repo may not permit redistribution)** —
  same as R2; explicit user declaration required.
- **R10 (LOW, template drift / staleness)** — `EXTRACTION.md` documents the
  `controller_compat: >=v0.x.y` frontmatter pattern for downstream use; this
  build does NOT ship it (deferred to v0.15.x).
- **R11 (LOW, skip button fatigue)** — per-project opt-out flag, default false
  (matches `phase_5_enabled: bool` pattern); auto-disable after 3 consecutive
  skips (deferred to v0.15.x).
- **R12 (LOW, over/under-generalization)** — `EXTRACTION.md` "what the agent
  can't decide" section explicitly enumerates the calls that are inherently
  human (brand generalization, trigger phrases on memory entries).
