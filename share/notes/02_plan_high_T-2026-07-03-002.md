# High-Level Plan — T-2026-07-03-002

**Date:** 2026-07-03
**Sub-agent:** planning

## Goal

Land a v0.13.0 memory system for the agents_manager controller: a three-scope memory tree (`global/` + `projects/<slug>/` + per-role `notes/{semantic,episodic}/`), a single canonical schema source-of-truth, a write-on-exit dispatch contract for specialists, a 90-day sweep at Phase 5 close, and a shipped validator — without changing any existing specialist behavior for non-substantive tasks and without touching the 11 + 19 v0.12.x follow-up files currently in flight.

## Non-goals

- **No content backfill.** The scaffold ships empty; operators (or their first task) write memory as it earns its keep.
- **No memory search/indexing.** File-based grep on the canonical README's keyword hints is the v1 search.
- **No per-agent context tuning.** All 7 agents share the same 200-lines-per-scope budget (R13 deferred).
- **No root `.gitignore` edits.** The root file is in the v0.12.x fence zone (`git status --short` has it modified); the plan uses a nested `agents_manager/memory/.gitignore` + a new `agents_manager/.gitignore` instead.
- **No `opencode.jsonc` edits.** The locked design enforces memory via SKILL.md + dispatch contract (R for opencode.jsonc moot).
- **No auto-commits, no auto-merges, no PR creation.** Per project convention.
- **No `agents_manager/master/` folder or `notes/` for master.** Master's memory is `share/notes/99_progress_<task-id>.md` (existing convention, unchanged).

## Approach

**Three-scope model, three writers, one schema.** Global + project scopes are master-written (cross-task + per-project learnings); each specialist writes its own role scope in the existing `agents_manager/<role>/notes/{semantic,episodic}/` folders that every SKILL.md already declares (but most folders are empty today). One canonical `agents_manager/memory/README.md` owns the schema, lifecycle, read/write protocol, durable-insight criteria, secrets-free rule, and validator reference; each per-role `notes/README.md` becomes a 2-line pointer (R7 mitigation). The validator (`scripts/validate-memory.sh`, ~50 LOC bash) ships in v0.13.0 as REQUIRED (not optional) so broken `superseded_by` links get caught mechanically (R1, R8).

**Five internal phases, all inside master's Phase 3 Build.** Each is a discrete am-coder dispatch with its own coder summary + review. The order is dependency-strict: scaffold (P1) → per-role scaffold (P2, references canonical from P1) → validator (P3, verifies scaffold) → specialist SKILL.md protocol injections (P4) → master SKILL.md + CLAUDE.md + CHANGELOG + final fence verification (P5). No phase can run before its predecessor. All five phases respect the v0.12.x fence — a per-phase `git status --short` check is mandatory so am-coder surfaces fence drift to master immediately.

**Master's edit to its own SKILL.md goes through am-coder** as a deliberate maintenance task (precedent: T-2026-07-03-001). This is surfaced for explicit user OK at Phase 2 confirmation, before any Build-phase dispatch. The 6 specialist SKILL.md updates and CLAUDE.md + CHANGELOG.md are similarly out of master's lane and routed through am-coder (R12, R14).

**CHANGELOG entry follows the v0.12.0 template** (What's new / Why / Files touched / Source attribution). A standalone draft lives at `share/notes/02_changelog_draft_T-2026-07-03-002.md` so am-coder pastes it verbatim into `agents_manager/CHANGELOG.md` during Phase 5 — no cherry-picking prose from a plan file.

## Risks acknowledged

- **R1 (validator optional → silently broken links)** — Validator is a REQUIRED deliverable in Phase 3, not optional. Dry-run verification confirms script + sample entry + scriptable exit codes before Phase 4 starts.
- **R2 (write-hygiene: specialists skip `Memory written:` on trivial dispatches)** — Protocol in Phase 4 says "only on substantive dispatches (the kind that hit `tasks/<id>.md` rows). Trivial status checks use `No memory write: trivial`." Thresholds embedded in canonical README.
- **R3 (write-honesty: specialists write fluff to satisfy)** — Canonical README defines a 3-question "durable insight" test (1) different agent in 3 months benefits? - **R4 (read-bloat: 200×3 = 600 LOC worst-case)** — Hard cap 200 lines per scope embedded in canonical README + validator guardrail; `last_verified > 90 days` sweep flagged at Phase 5 close.
- **R5 (stale memory: agent trusts a no-longer-true entry)** — Every entry's TL;DR ends with `Verify against: path:line`. 90-day sweep at Phase 5 close per R2 / locked design 5.
- **R6 (cross-project contamination)** — `scope: project` tag + active-slug grep-before-read protocol. Documented in canonical README.
- **R7 (schema drift across 7 specialists' READMEs)** — One canonical schema source-of-truth at `agents_manager/memory/README.md`. Per-role READMEs are 2-line pointers (locked design). Phase 2 enforces this on day one.
- **R8 (supersession gap: `superseded_by` to nonexistent file)** — Validator enforces link resolution in Phase 3.
- **R9 (cold-start tax: first-ever project gets nothing)** — Accepted for v0.13.0 (no content backfill). Documented as non-goal; `bin/install.sh --memory-seed` deferred to v0.13.1+.
- **R10 (operator migration: existing `notes/` content)** — Co-exist scaffold (no rename, no relocate). Documented in CHANGELOG + canonical README.
- **R11 (read-time token cost: ~2k tokens per dispatch on memory alone)** — Accepted for v1 (scaffold empty → 0 cost; 90-day sweep keeps it bounded). Revisit at v0.15.x if metrics show re-entry memory growing >5% of total context.
