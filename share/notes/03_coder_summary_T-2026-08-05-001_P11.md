## Design decisions worth reviewing

1. **Missing-`mmdc` policy is split, not a flat hard fail.** Dispatch said "runtime check at script entry ... exit non-zero" and left the orchestrator handling to my call. Implemented:
   - blocks found + no `mmdc` -> **exit 3**, nothing written (a raw mermaid fence must never reach the PDF)
   - no blocks + no `mmdc` -> stderr warning, empty manifest, **exit 0** (a prose book with no diagrams must not break the pre-PDF step)

   A flat exit-3 would fail every diagram-free book. Documented in the docstring, SCRIPTS.md, and the SKILL.md Phase 6 paragraph.
2. **Parse-then-write.** Every chapter is parsed before the first byte is written, so one malformed block leaves `figures/` and `chapters-rendered/` untouched instead of half-written.
3. **Caption resolution** (not specified in the plan, which only says `![<caption>]`): `%% caption:` directive -> nearest preceding heading -> `Figure <idx>`.
4. **Manifest stability.** Records sorted by `(chapter, index)`; `source_hash` = sha256 of block source. `test_manifest_is_stable_across_reruns` asserts byte-identical output across two runs with filesystem-order-independent sorting.

## New WARNs surfaced (LOW only — auto-acceptable)

- **P11 — LOW** — `render_book()` recreates `.mmd` files and re-invokes `mmdc` on every run even when `source_hash` is unchanged from the existing manifest. Re-runs are correct and byte-stable but not incremental; on a large book every pre-PDF pass re-renders every diagram. A future pass could read the existing manifest and skip blocks whose hash matches. Not a correctness gap — `book-kit/book_workflow/scripts/render_mermaid.py` `render_book()`
- **P11 — LOW** — Stale figures are never garbage-collected. If a chapter drops from 3 mermaid blocks to 2, `<slug>-ch-NN-mermaid-3.png/.mmd` remain on disk; they fall out of the manifest (so downstream consumers are correct) but linger in `figures/`. A `--prune` flag would close this — `render_book()`
- **P11 — LOW** — `_relative_link()` computes the mirror-to-figures link from `--out` to `--figures-dir`. With the defaults this yields the correct `../figures/...`; a caller who nests `--out` deeper still gets a correct relative path via the `os.path.relpath` fallback, but the link is only asserted for the default layout in tests — `render_mermaid.py` `_relative_link()`
