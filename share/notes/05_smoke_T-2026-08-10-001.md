## Bugs found (real, not WARNs)

### Bug #1 â€” `assemble_audiobook.py` self-check counts from manifest products, not actual chapter count
**Severity:** MEDIUM (output M4B itself is correct; only the self-check assertion is wrong)
**Location:** `book-kit/book_workflow/scripts/assemble_audiobook.py:_expected_chapter_count`
**Repro:** `assemble_audiobook.py --self-check --book books/daily-focus-smoke --locale ar` (manifest has 2 products: en + ar)
**Observed:** `chapter_count=1 expected=2` â€” self-check FAIL despite a valid 1-chapter M4B
**Fix:** Compute expected from actual input chapter count (`_load_chapter_ids(...)` length), not manifest `len(products)`.
**Effort:** ~5 lines + 1 test

### Bug #2 â€” `assemble_reel.py` multi-platform filter graph had unlabeled input on `split`/`asplit`
**Severity:** HIGH (reel 3-platform fan-out produced zero-byte stub MP4s, ffmpeg rc=-22 EINVAL)
**Location:** `book-kit/book_workflow/scripts/assemble_reel.py:L485-493, L512-513`
**Status:** **FIXED** during smoke (agent dispatch m0222). Now `[v_base]split=3[v_yt_in][v_ig_in][v_tiktok_in]`.
**Why Phase 4 review missed it:** Tests mock `subprocess.run`, so the filter graph is never actually fed to ffmpeg.
**Takeaway:** Need at least 1 integration test per CLI that runs real ffmpeg on a 5-frame dummy input.

### Bug #3 â€” `assemble_reel.py` encode preset `yuv444p` (4:4:4) too heavy for 3-parallel fan-out
**Severity:** HIGH (any 3-platform render OOMs at encode time, even with pix_fmt unrelated to fan-out)
**Location:** `book-kit/book_workflow/scripts/assemble_reel.py:L391, L563`
**Status:** **FIXED by master tactical 1-line patch** (Phase 3 L369 pattern, accepted for clear-cut bugs). Now `yuv420p` (4:2:0) â€” standard delivery chroma.
**Why:** 4:4:4 is 3 bytes/pixel vs 4:2:0's 1.5 bytes/pixel = 50% less memory per frame, and libx264 4:4:4 is much slower.

### Bug #4 â€” Reel multi-platform fan-out OOMs on this hardware even after pix_fmt fix
**Severity:** HIGH (3 parallel libx264 1080p encoders at yuv420p still OOM at 3-4% free RAM)
**Root cause:** CPU+memory contention when ffmpeg tries to encode 3 outputs in one invocation, even at 4:2:0
**Workaround for smoke:** Use single-platform path (`--platforms yt`) OR direct ffmpeg cmdline (proven: 6:13 for 60s EN reel)
**Architectural fix:** Serial architecture â€” for N platforms, run N ffmpeg invocations sharing the source render. Each invocation = 1 encoder, less peak memory.
**Effort:** ~30 lines + 2 tests

### Bug #5 â€” Arabic SRT alignment drift 90% (chunker+Whisper-large-v3 mismatch)
**Severity:** HIGH (Arabic captions broken end-to-end; blocks AR video with subs)
**Location:** `book-kit/book_workflow/scripts/align_srt.py:76` (DRIFT_RATIO_FLOOR = 0.70)
**Observed:** `ratio=0.103 < 0.70` for AR
**Likely cause:** Arabic diacritics normalization mismatch between chunker text (raw) and Whisper transcription (lowercased + diacritics-stripped). May also be chunker sentence-boundary tokenization differs from Whisper's.
**W2 deferred WARN (no `--drift-floor` CLI flag) becomes critical** â€” need to expose this AND investigate the underlying text-mismatch root cause.
**Effort:** Root-cause investigation + W2 fix together: ~30 lines
