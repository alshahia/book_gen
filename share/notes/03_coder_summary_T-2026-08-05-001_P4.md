## Drift note (explicit — required by dispatch)

The working tree drifted after commit `8fbd396`. The drift, as observed before `git checkout HEAD --`, was that `book-kit/book_workflow/scripts/render_ledger_check.py` had been partially rewritten to expose a simpler top-level `render(check_chapter, book_check, chapter_label)` function. That rewrite had three observable properties: (a) `render()` returned a `(markdown, exit_code)` tuple rather than the pure `block_markdown` that `build_gate_block` returns; (b) it lost `write_into_ledger` entirely; (c) it was 312 CRLF lines instead of the canonical 394 — about 80 lines fewer. The drift broke the test contract because the four committed tests import `rlc.build_gate_block` and `rlc.write_into_ledger` directly — `pytest` would have surfaced `AttributeError: module 'render_ledger_check' has no attribute 'build_gate_block'` on the drifted tree.

The drift was discarded via `git checkout HEAD -- file` because: (1) the four committed tests are part of the test contract — the suite passes only when the canonical API surface is restored; (2) the canonical implementation is well-tested and its idempotent ledger-replace behavior is what the orchestrator's Phase 6 paragraph (4. above) tells master to rely on; (3) the simplification would have given up the granular helpers (`_row_frozen_lines`, `_per_chapter_ratio`, `_row_cross_ref`, `_row_from_check_chapter`) that isolate the per-rule logic for future P5/P8 consumers (bible.md applicability table + continuity anchors both need the same per-rule decomposition). A future cleanup pass that wishes to refactor the API must rebake the test signatures onto whatever the new shape is — that is a deliberate refactor, not a fix-loop.

The other two working-tree modifications (`share/notes/99_decisions.md` and `tasks/T-2026-08-05-001.md`) are master-owned files and were not touched by this dispatch, per the boundary contract.
