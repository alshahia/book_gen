## Implementation notes

### `book_check.py` additions

1. **`_force_utf8_stdio()`** — module-internal helper that reconfigures
   `sys.stdout` / `sys.stderr` to UTF-8 before any `Coin arc:` / `Motif
   arc:` print. Inherits the WARN #15 + #22 lesson from P4/P5: when
   non-ASCII chars (em-dash U+2014, arrow `->`) hit stderr on Windows
   cp1256, the print crashes. Forced only inside the P8 block (not at
   module top — pre-existing code already prints non-ASCII via
   `ensure_ascii=False` JSON without forcing, and forcing module-wide
   would be an out-of-scope behavior change).

2. **`parse_bible_anchors(path)`** — regex `r"##\s+Continuity anchor\b"`
   finds one-or-more `## Continuity anchor` sections in
   `books/<slug>/bible.md`. Each section contains a markdown table with
   three columns `Keyword | Quote | Scope`. The `Scope` cell matches
   `r"ch[-\u2013](\d+)\s*(?:\.\.|[-\u2013\u2014])\s*ch[-\u2013](\d+)"`
   which accepts both ASCII `-` and en-dash U+2013 (WARN #19
   inheritance). The `Quote` cell has surrounding ASCII / smart quotes
   stripped (`re.sub(r'^["\u201c\u2018]+|["\u201d\u2019]+$', '', quote)`)
   so a writer who types `"glinted in the light"` in the table resolves
   to the bare phrase. Separator / header / empty-keyword rows are
   skipped silently.

3. **`_check_continuity(book_root, anchors)`** — for each anchor,
   enumerates `chapters/ch-NN.md` in `scope_start..scope_end` range,
   checks whether the keyword substring is present (case-insensitive),
   and emits a `Coin arc:` line. Labels follow the spec example
   exactly: `(introduced)` for the first hit, `(mentioned)` for middle
   hits, `(paid)` for the last hit, `(solo)` for single-chapter arcs,
   `(missing)` for chapters where the keyword is absent. The `Quote`
   is stored for reference but is NOT required to repeat verbatim
   across chapters — only the keyword carries the arc (matches the
   spec's example row `ch-01 (introduced) → ch-03 (mentioned) → ch-05
   (paid)` where the keyword is the persistent motif).

4. **`parse_tracked_motifs(path)`** — regex `r"##\s+Tracked motifs"` in
   `books/<slug>/style-guide.md`. Each non-empty bullet line becomes
   one motif; trailing `:<reason>` text is stripped
   (`re.match(r"^[-*]\s+(.+?)(?:\s*:.*)?$", line)`).

5. **`coin_arc(book_root, motifs)`** — for each motif, walks every
   `chapters/ch-*.md` (sorted, case-insensitive substring match) and
   emits a `Motif arc:` line with the same label scheme.

6. **`main()` integration** — block inserted between the cross_ref
   check (line 345-382, P3) and the summary block (line 384-409).
   Reads bible.md + style-guide.md, runs both checks, emits one stderr
   line per anchor / motif, and contributes any FAIL to the existing
   `failed` flag.

7. **`summary.checks`** — gains two new keys `continuity` (count of
   FAIL anchor rows) and `coin_arc` (count of FAIL motif rows).

8. **JSON payload** — gains two new top-level keys `continuity` (list
   of anchor result dicts) and `coin_arc` (list of motif result
   dicts), each shape `{keyword|quote|motif, scope, arc, status,
   chapters_missing}`.

9. **`--self-check`** — added self-check #5 that creates a 3-chapter
   fixture with a `silver coin` continuity anchor (PASS) and a
   `compass` + `locket` tracked motifs block (both FAIL). Asserts on
   the JSON fields `data["continuity"][0]["status"] == "PASS"` and
   `data["summary"]["checks"]["coin_arc"] == 2`.

## Deviations from spec

| `_check_continuity(book_root, anchors)` checks "keyword + quote adjacency" | Keyword-only substring check; `quote` is stored but not required to repeat verbatim in every chapter | Spec's example row `ch-01 (introduced) → ch-03 (mentioned) → ch-05 (paid)` shows the KEYWORD persisting (not the quote). Quote is preserved in the result dict for documentation and can be re-introduced as a stricter mode in a future P8.x pass. |

The dict field `arc` uses ASCII `->` so the JSON payload is portable across all terminals and downstream consumers (render_ledger_check, gate_summary) don't need a UTF-8 stdio dance to read it. Same dict shape; display differs. |
