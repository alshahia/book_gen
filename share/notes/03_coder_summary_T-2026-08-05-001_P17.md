## Invocation Count Design Decision

**Picked option (b): `--reviewer-invocations N` CLI flag.**

Rationale: `gate_summary.py` runs as the **pre-review** gate artifact (before `am-review` writes its report per the Phase 7 spec), so option (a) "read invocation count from the reviewer's own output" has a chicken-and-egg ordering problem — the gate artifact must exist before the reviewer is dispatched. Option (b) is a clean CLI addition that:
- Doesn't require any change to the reviewer's output contract
- Gives master explicit, observable control over the reported N
- Surfaces the chunk count + fallback retries in the dispatch prompt so the reviewer knows how many total calls it should expect
- Keeps the gate artifact self-describing (no hidden state)

Default value is 1 (single-pass review, the historical behavior). Master computes N from the chunking run + fallback attempts and passes it on the CLI; the artifact records N verbatim so downstream consumers can audit how much review budget the chapter consumed.

The dispatch's option (c) (parse WARN/CRITICAL counts) was rejected as too lossy — chunk count and retry count are not derivable from the verdict counts.

## Chunking Helper Decision

**Kept `chunk_for_review()` as a private pure function in `test_gate_summary.py`.** Did NOT create `chunk_chapter.py` helper.

Rationale: the spec test ("1 fixture chapter with 3000 words -> orchestrator runs 4 chunks -> 1 consolidated review") requires the algorithm to be testable. Putting the function in the test file:
- Stays within the dispatch's 4-file touch boundary
- Mirrors how `test_gate_summary.py` already imports `gate_summary as gs` and tests internal helpers like `_derive_status` and `render_gate`
- Avoids adding new production surface area
- The SKILL.md describes the algorithm to `am-review` (which doesn't read Python), so the test verifies the algorithm produces the expected chunk counts when invoked against the spec fixture

The algorithm:
1. If `words <= max_tokens` -> return `[text]` (one chunk)
2. Otherwise split at `### ` H3 headings (zero-width lookahead keeps H3 attached to its section)
3. Greedily group consecutive sections into chunks with cumulative words <= `max_tokens`
4. If a single section exceeds budget, fall through to paragraph-level splitting, then word-window last resort (defensive path)

This matches the orchestrator's Phase 7 "splitting strategy" semantics and is exercisable directly via `import` in tests.
