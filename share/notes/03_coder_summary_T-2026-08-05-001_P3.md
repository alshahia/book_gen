- **Integration structure is inline, not a `_check_cross_ref()` function.** The dispatch prompt suggested "Confirm a `_check_cross_ref(book_root)` function exists". The pre-existing partial edit placed the logic inline in `main()` (lines 345-382 of `book_check.py`), consistent with how the file's other checks (fence balance, missing_h2, etc.) are also inlined. I verified the inline block satisfies all the prompt's functional requirements (chapters-exists gate, FAIL/PASS stderr, summary counter, JSON payload field, try/except fallback). Refactoring into a function would diverge from the file's existing style without adding value, so I left the inline approach intact.
- **H1 headings in test fixtures use plain "Title" not "Chapter N".** The cross_ref spec treats `chapter N`/`Ch. N`/`ch. N` as cross-references. If test chapters had `# Chapter 1`, the resolver would self-flag ch-01 (its own H1 would resolve to its own H2 — but only if ch-01 had a matching H2, which my clean fixtures don't). Using `# Title` makes fixtures deterministic and matches `test_check_chapter.py`'s style.
- **`test_arabic_numerals` includes a heading ref as well as the source ref.** The fixture has `## الفصل 3` in ch-03.md (an H2 that itself counts as a self-ref to ch-03) plus `الفصل ٠٣` in ch-04.md. Total = 3 resolved, 0 broken. The test asserts exact equality to lock the behavior — if the heading-self-ref rule changes in the future, this test will catch it.

## Known issues / TODOs left in code

- **`slugify()` does NOT normalize Arabic-Indic digits inside anchor text.** A heading like `## القسم ٠٣` slugifies to `القسم-٠٣` while a ref `(ch-NN.md#القسم-03)` slugifies to `القسم-03` → false broken. Uncommon in current corpus (translation-mode book would have to mix scripts across heading text and ref text) but real. Documented in WARN register as P3-LOW.
- **`_is_in_url()` heuristic is broad.** Matches any `https?://\S*$` substring before the match on the line — correctly suppresses `https://example.com/ch-03` false positives but also suppresses a `[ch-03]` that follows a URL mention with intervening text. Acceptable trade-off for the cheap regex; document if a real case surfaces. Documented in WARN register as P3-LOW.
