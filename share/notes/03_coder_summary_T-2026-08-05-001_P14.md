## File-count decision (5 vs 6)

The dispatch noted "P14 has TWO new scripts (`pin_deps.py` + `check_chapter.py` extension) plus TWO test files plus docs. That's 6 minimum." I went with **6 atomic** because:

- `pin_deps.py` and the `check_chapter.py` extension are two distinct deliverables — splitting them into P14a/P14b commits would require two review cycles instead of one and is purely cosmetic.
- The 4-file convention is a guideline, not a hard rule (P13 was 4, but its source/test/docs split matches P11/P12 exactly; P14 is the first phase to touch a second source file).
- Combining the two test files into one (`test_pin_deps.py`) is feasible but the test groups are conceptually independent (pin_deps.py has its own pytest setup; check_chapter.py tests are interleaved with 15 baselines) — keeping them separate is easier for grep discovery and matches the existing test file naming convention.
- One atomic commit is what the plan §P14 verbatim says.

If a reviewer prefers the split, the same SHA can be split into P14a (3 files, pin_deps.py + test + SCRIPTS) and P14b (3 files, check_chapter.py + test + SKILL.md) without changing the artifact — both reviews land on the same code.

## Known issues / LOW WARNs surfaced

- **(LOW)** `pin_deps.py:lock_status` is the literal string from a fixed enum (`pinned` / `no_deps` / `uv_missing` / `compile_failed` / `missing_input`); the spec example shows `{chapter, packages, lock_status}` with `lock_status: "pinned"` but does not enumerate the failure modes. The enum is documented in the module docstring + status table — not a deviation, just an extension of the spec's example.
- **(LOW)** `check_imports` only matches `from X import Y` lines (per spec verbatim: "for each `from X import Y` in code listings"). Bare `import x` statements are not counted. This is consistent with the plan; defensible because the dominant Python dependency-pinning convention is `from package import name`. Future P14.x candidate: extend the regex to also match bare imports if real-world chapters surface a gap.
- **(LOW)** `check_imports` matches package name case-insensitively (PyPI canonical casing) but does NOT handle namespace packages or distribution-vs-import-name mismatches (e.g. `from PIL import Image` -> import `PIL` but the lock file pins `Pillow`). A future P14.x can add a `import_name -> distribution_name` mapping table.
- **(INFORMATIONAL)** `pin_deps.py` writes `uv.lock` with full annotation comments when uv emits them (`# via -r requirements.txt`). The lock parser skips `#`-prefixed lines, so this is benign; just documenting for the reviewer.
