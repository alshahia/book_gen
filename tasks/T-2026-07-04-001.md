## Decisions made in this plan (master-approved defaults)

- **Standard file lives at `templates/AUTHORING.md`** (not in `agents_manager/standards/`).
  Rationale: it's the rulebook for the `templates/` tree, so it sits at the root
  of that tree. Same lane as the templates themselves.
- **Authoring standard version starts at v1.0.0** (not v0.1.0). Rationale: the
  standard IS the contract; v1 signals "this is the rulebook you should write
  to" rather than "draft." Future patch/minor/major bumps per the Versioning
  section at the end of AUTHORING.md.
- **cinematic-landing bumps 0.12.1 → 0.13.0** (not 0.12.2). Rationale: the
  template's *external contract* changes — every consumer now expects an
  `INDEX.md` and `tests/verify.sh`. Per semver that is a minor bump on the
  template's API.
- **The 9 fixes from cinematic-landing-fixes.md are applied as a single
  am-coder dispatch** (not 9 separate dispatches). Rationale: they are all
  small edits to the same template; serializing them across dispatches would
  cost >5x the wall-clock for no review-quality gain. The review phase catches
  per-fix defects.
- **Decision log entry for deferred `am-assets` specialist** (Fix 8) is part of
  the coder's P3T8 — single dispatch.
- **No new template is authored in this task.** Rationale: user asked for the
  *standard*, not a second template. The standard's quality is judged by
  whether it WOULD have prevented the 9 fixes from being needed.
- **Ponytail-mode stance: no frontmatter on `templates/<name>/memory/*`** —
  confirmed by `agents_manager/research/notes/semantic/template-memory-cp-fence.md`
  and consistent with the existing 14 files in `templates/cinematic-landing/memory/`.
- **`templates/AUTHORING.md` gets minimal frontmatter** (`scope`, `topic`,
  `status`, `version`, `created`, `last_verified`) — it is a *meta* doc, not a
  memory file, and the fence doc's no-frontmatter rule does not extend to meta
  files. The frontmatter is light; nothing exotic.
- **`templates/CONTRIBUTING.md` is added as a sibling to AUTHORING.md** —
  the discoverable entry point for contributors adding a new template.
  CONTRIBUTING.md points to AUTHORING.md (the rules), references
  `templates/_blank/` (the starter), and gives a step-by-step recipe. Standard
  GitHub convention; familiar to anyone who has opened a PR.
- **`templates/_blank/` is added as a starter template** — the minimal legal
  template (every required file, no content). Contributors `cp -r _blank/
  <their-name>/` and fill it in. Without a starter, the standard's rules are
  abstract; with a starter, they are copy-modify-commit.
- **The AUTHORING.md "For authors" section is strengthened** with a more
  detailed step-by-step recipe (P3T15). The current 6-step version is decent
  but abstract; the strengthened version shows what each step's output looks
  like, with a worked-example trace.
- **Coverage-audit gaps are now in scope** — the three gaps from the previous
  turn's coverage audit (P3T3b trigger retrofit on 01–09, P3T10b consumer
  walkthrough in INDEX.md, P3T14 recipe + neutral worked example, AG19
  empirical agent-usability gate) are promoted into this plan so coverage of
  the user's original intent reaches ~95% instead of ~75%.

### P3T11 brief — tests/verify.sh

**Read first:** `share/templates/AUTHORING.md` Rule 4.

**Create:** `templates/cinematic-landing/tests/verify.sh` — bash, executable, one
test per README/INDEX claim:

```bash
#!/usr/bin/env bash
# Verify every grep-able claim in INDEX.md + README.
# Exit non-zero on first failure.

set -euo pipefail

SKELETON="skeleton/index.html"
MEMORY="memory"
MANIFEST="assets/MANIFEST.txt"

# T1: 8 sections exist with data-section attribute
test_sections_have_data_section() {
  local count
  count=$(rg -c 'data-section="' "$SKELETON" || true)
  if [[ "$count" -lt 8 ]]; then
    echo "FAIL: expected ≥8 data-section attributes in skeleton, got $count"
    return 1
  fi
}

# T2: no frontmatter on memory files
test_no_frontmatter_on_memory() {
  if rg -l '^---$' "$MEMORY"/*.md 2>/dev/null; then
    echo "FAIL: frontmatter found in memory/ (forbidden)"
    return 1
  fi
}

# T3: MANIFEST entries resolve
test_manifest_resolves() {
  while IFS= read -r line; do
    line="${line%%#*}"           # strip comments
    line="${line// /}"            # strip whitespace
    [[ -z "$line" ]] && continue  # skip blanks
    [[ ! -e "$line" ]] && {
      echo "FAIL: MANIFEST entry does not resolve: $line"
      return 1
    }
  done < "$MANIFEST"
}

# T4: H1 number matches filename prefix
test_h1_matches_filename() {
  for f in "$MEMORY"/*.md; do
    local prefix
    prefix=$(basename "$f" | grep -oE '^[0-9]+')
    local h1
    h1=$(head -n 1 "$f" | grep -oE '^[0-9]+' || true)
    if [[ "$prefix" != "$h1" ]]; then
      echo "FAIL: $f prefix=$prefix but H1=$h1"
      return 1
    fi
  done
}

# T5: contrast values match memory/14 canonical
test_ink_faint_is_7a6855() {
  if ! rg -q '\-\-ink-faint:#7A6855' "$SKELETON"; then
    echo "FAIL: --ink-faint must be #7A6855 per memory/14"
    return 1
  fi
}

# T6: cutout image is distinct from aura image
test_cutout_distinct_from_aura() {
  local aura cutout
  aura=$(rg -o 'aura.*pexels\.com/photos/[0-9]+' "$SKELETON" | grep -oE '[0-9]+' | head -1 || true)
  cutout=$(rg -o 'cutout.*pexels\.com/photos/[0-9]+' "$SKELETON" | grep -oE '[0-9]+' | head -1 || true)
  if [[ -n "$aura" && "$aura" == "$cutout" ]]; then
    echo "FAIL: aura and cutout share Pexels ID $aura"
    return 1
  fi
}

# T7: no phantom specialists in MANIFEST
test_no_phantom_specialists() {
  if rg -q 'agents_manager/assets/' "$MANIFEST"; then
    echo "FAIL: MANIFEST references non-existent agents_manager/assets/ subtree"
    return 1
  fi
}

# T8: typo check (hrief.md)
test_no_hrief_typo() {
  if rg -q 'hrief' .; then
    echo "FAIL: hrief.md typo survived"
    return 1
  fi
}

# Run all
test_sections_have_data_section
test_no_frontmatter_on_memory
test_manifest_resolves
test_h1_matches_filename
test_ink_faint_is_7a6855
test_cutout_distinct_from_aura
test_no_phantom_specialists
test_no_hrief_typo

echo "OK: all verify.sh checks passed"
```

(PowerShell-compatible variant noted in a comment at the top for Windows
contributors.)

**Acceptance:** `bash tests/verify.sh` from `templates/cinematic-landing/`
exits 0 after all fixes are applied.
