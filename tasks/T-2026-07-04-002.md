## CSS conventions

When adding a new section, follow these conventions:

- **Outer wrapper:** `<section id="<id>" data-section="<id>"
  data-ambient="<hex>" data-ambient-dark="<hex>">` — schema is
  non-negotiable (see `## Hard rules`).
- **Inner container:** `<div class="container">` for max-width
  centring. Reuse; do not redefine.
- **Cards / articles:** `<article class="<thing>-card">` for any
  repeated card-like content (e.g., `testimonial-card`, `ed-card`).

  quotes) over `<div>` soup.

- **Ambient color shift:** provided by JS that reads
  `data-ambient`/`data-ambient-dark`. Do not hardcode `background-color`
  on the section element.
- **Fictitious content:** when adding demo copy, add an HTML comment
  at the top of the section: `<!-- fictitious names; replace before
  production -->`. Real names go through review.
```

# T1: exactly N distinct data-section values, where N is the section
# count declared in INDEX.md
test_sections_exact_and_distinct() {
  # Pull N from INDEX.md "## Sections (N)"
  local n_index
  n_index=$(rg -o '## Sections \(([0-9]+)\)' "$INDEX" | grep -oE '[0-9]+' | head -1)
  if [[ -z "$n_index" ]]; then
    echo "FAIL: cannot parse '## Sections (N)' from $INDEX"
    return 1
  fi
  # Count distinct data-section values in skeleton
  local n_actual
  n_actual=$(rg -o 'data-section="[^"]+"' "$SKELETON" | sort -u | wc -l)
  if [[ "$n_actual" -ne "$n_index" ]]; then
    echo "FAIL: INDEX says $n_index sections but skeleton has $n_actual distinct data-section values"
    return 1
  fi
  # Verify each data-section value is unique (no duplicates)
  local dup_count
  dup_count=$(rg -o 'data-section="[^"]+"' "$SKELETON" | sort | uniq -d | wc -l)
  if [[ "$dup_count" -ne 0 ]]; then
    echo "FAIL: $dup_count duplicate data-section value(s) in skeleton"
    return 1
  fi
}
```

Replace the old T1 call with `test_sections_exact_and_distinct`.
