# Task — T-2026-07-04-003

**Created:** 2026-07-04

**Predecessor:** T-2026-07-04-001 (v0.14.0 baseline; AG16 audit flagged WARN-9 as informational; not patched in fix-loop-2)
**Trigger:** am-design AG16 audit — keyboard-only users cannot Tab to 5 body sections because per-section containers aren't focus-receivable; only interactive elements inside are reachable. Informational per am-design's verdict ("not material to ship, defer").
**Goal:** triage the 5 unreachable sections; decide which (if any) need a focus-receiver pattern + skip-link; ship the agreed fix as a minimal patch.

## User intent (literal)

Keyboard-only navigation should be able to reach every body section, either by Tab-stop inside the section or by skip-link / landmark navigation. Right now 5 of 8 body sections are unreachable from the keyboard alone. We need to know which is the right fix per section and ship it.

## Decisions (master-approved defaults)

- **Triage first, fix second.** am-design produces a per-section decision; am-coder applies the agreed fix. No speculative patches.
- **Per-section fix taxonomy:**
  - **Skip-link:** add `<a href="#<id>">skip to <section></a>` near the top of the previous section. Cheap, no JS.
  - **Focus-receiver:** add `<section ... tabindex="-1">` so the section itself is focus-targetable but not in the Tab order; `<h2>` inside gets `tabindex="-1"` + visible focus ring on programmatic focus.
  - **Accept-as-design:** the section has no actionable content beyond its inner interactive elements; no fix needed. Cite the reasoning.
- **Each section gets ONE decision.** Mixed approaches within a section are forbidden.
- **WARN-9 stays informational in this task** if am-design's triage concludes the issue is acceptable. The task is a *triage*, not a forced fix.

## Out of scope

- Full WCAG 2.2 audit beyond keyboard reachability (covered by future AG16 rerun if requested).
- Replacing Tab navigation with arrow-key roving patterns (out of scope; defer).
- Skip-link styling review (just functional placement; visual review is a separate task).

### T2 brief — am-coder fix application

**Files to read first:**
- T1's triage output at `share/reports/04_design_T-2026-07-04-003_triage.md`
- `templates/cinematic-landing/skeleton/index.html` (current state)
- `templates/cinematic-landing/memory/13-keyboard-nav.md` (do not contradict)

**Edits:** apply the markup delta for every row where Decision ≠ accept-as-design:

- **Skip-link insertions:** add `<a class="skip" href="#<id>" data-skip-link>Skip to <section name></a>` as the LAST element of the previous section's container. Style in CSS:
  ```css
  .skip { position: absolute; left: -9999px; }
  .skip:focus { left: 1rem; top: 1rem; background: var(--paper); padding: .5rem 1rem; z-index: 100; }
  ```
  (Ponytail: simplest pattern that works. SR + keyboard users get the link on focus; mouse users never see it.)

- **Focus-receiver markup:** add `tabindex="-1"` to the section element. Optionally add `tabindex="-1"` to the section's `<h2>` and a CSS rule:
  ```css
  h2:focus-visible { outline: 2px solid var(--gold); outline-offset: 4px; }
  ```

- **Accept-as-design:** no edit; record the decision in the WARN register.

**Acceptance:** markup delta from T1's table applied verbatim; no edit outside the agreed scope; `bash tests/verify.sh` exits 0 (T1's edits should not break any test, but the coder must confirm).
